# Flounder: сценарий демо 15.10.2026

План — **14 минут**, семь шагов, резерв до 15 минут. **17.10.2026 — пример ближайшей субботы для недели релиза**: сид рассчитывает дату нового события от момента запуска, поэтому при более позднем запуске она сдвинется. Существующее событие сохраняет свою дату. У соревнования сессии 10:00 и 15:00 по Самаре (UTC+04). Дата соревнования берётся из вывода сида; показ продукта проходит 15.10.2026. Репетиция — 14.10 вечером, времена организационных встреч ниже по Москве (UTC+03).

Роли: Сергей ведёт показ и переключает организатора; второй участник показывает родителя на телефоне; секретарь вводит результаты; судья проверяет ввод; ответственный T09 следит за стендом и резервом. Перед репетицией Сергей назначает конкретных людей на эти роли. Аккаунты: `admin@flounder.demo`, `org@flounder.demo`, `sec@flounder.demo`, `judge@flounder.demo`, `parent@flounder.demo`. Пароли передаются ведущему через окружение/локальный `.env`; на экране и в сценарии их не показываем.

Старую площадку без метаданных нужно исправить в БД или создать заново, API обновления нет; для всех семи шагов нужны также T02/T04/T06/T07/T08/T09. Резервное событие создать командой `EVENT_TITLE_SUFFIX=" · резерв" npx tsx seed.ts`, затем провести прогон; для его сброса использовать тот же суффикс. Основное событие запускать без суффикса. Сид открывает регистрацию: для отдельного DRAFT-резерва не считать этот запуск готовым — использовать подготовленное в UI DRAFT-событие. У ссылок и PDF отметить дату и слово «резерв». Переключение на резерв объявляем зрителям; его успех не засчитываем как успех основного стенда.

### 6. Снятие участника и пересчёт — 9:45–11:00 (1 мин 15 с)

**Роль:** организатор.

**Реплика:** «Участница снялась со старта. В опубликованном протоколе мы сохраняем дорожки остальных участников, а снятую отмечаем отдельно. Расписание можно пересчитать. Если участник уже оплатил взнос, возврат оформляется по правилам организатора; автоматического возврата в этом демо нет, снятие само по себе деньги не возвращает».

**Показать:** выбрать одну заявку **F-100-FREE** из позднего дневного заплыва, который не используется на шаге 7. Записать фамилию, номер заплыва и дорожки соседей до действия. Снять заявку: `WITHDRAWN`. Для опубликованного заплыва показать снятую/пустую дорожку без перестановки остальных, затем «Пересчитать расписание» (`POST /events/{id}/schedule/recalculate`), обновить протокол и валидатор: WARNING об изменении опубликованного заплыва, 0 новых ERROR. Сравнить соседние дорожки до/после.

**Особенность контракта:** §5.5 запрещает обычную повторную генерацию при наличии `PUBLISHED` (409), а `force=true` перестраивает всё. Поэтому в этой последовательности используем снятие и пересчёт расписания, ожидая обработку снятия по US-5. На репетиции подтвердить с T02/T03, что снятие обновляет дорожку и WARNING без полной генерации. Если UI «Пересчитать» вызывает генерацию с force, этот путь для опубликованных заплывов не использовать.

**Запасной ход:** если получен 409, показать понятный запрет и не обходить его полной перестройкой. На отдельном резервном DRAFT-событии показать снятие и обычный повторный посев; явно назвать различие статусов. Если опубликованный заплыв не изменился, зафиксировать дефект US-5, показать снимок ожидаемого поведения и продолжить. Не делать ручные SQL-правки.

## Вопросы для согласования до репетиции

1. Есть ли у существующей площадки фактически сохранённые `venueMeta`? T01 поддерживает поле; на слитом main проверить строгий режим, при отсутствии метаданных исправить их в БД или создать площадку заново.
2. Какой UI-путь выполняет US-5 для опубликованного заплыва без перестановки дорожек, с учётом 409/force в §5.5? На репетиции нужен подтверждённый путь «снять → пересчитать расписание → проверить WARNING».
3. Кто назначен на роли родителя, секретаря, судьи и T09, где расположены основной/резервный стенды и закрытое хранилище копии БД?

Регистрация демо-события автоматически закроется в 09:30 Самары в день старта (05:30 UTC). Организатор может закрыть её вручную или продлить, указав новую будущую дату. Лимиты события, вида и возрастных групп опциональны: демо-сид их не задаёт. При заполнении лимита новая заявка попадает в «Лист ожидания» с номером очереди; освобождение места или повышение лимита переводит первую подходящую заявку в «Подана». После завершения событие можно архивировать: публичные страницы сохраняются, изменения блокируются. Повторный сид закрытого события продолжает импорт с предупреждением и не открывает регистрацию.

### S07: сотрудники организации
С S07 глобальные роли `operator`/`judge` для `sec@flounder.demo` и `judge@flounder.demo` больше не обязательны: права секретаря и судьи даёт соответствующее членство в организации. После обновления проверить вход и доступ демо-аккаунтов, включая доступ судьи после снятия глобальной роли.
