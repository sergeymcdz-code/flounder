# SportGate: сценарий демо 19.10.2026

Показ — 14 минут, резерв до 15 минут. Репетиция — 17.10.2026, организационное время по Москве. Все даты соревнований задаёт `DEMO_DATE=2026-10-19`; часовой пояс бассейна — Europe/Samara (UTC+04). Первая сессия каждого события начинается в 10:00, вторая — в 15:00 местного времени (09:00/14:00 МСК).

| Событие / slug | Назначение | Дата от демо | Статус |
|---|---|---|---|
| A `kubok-sportgate-osen` — «Кубок SportGate — осень» | Прошедшее: итоговый протокол, медалисты, исправления | −8 дней, 11.10 | COMPLETED |
| B `otkrytyy-kubok-samary-po-plavaniyu` — «Открытый кубок Самары по плаванию» | Ближайшее: импорт M, готовый посев, стартовые протоколы, live | +1 день, 20.10 | REGISTRATION_CLOSED |
| C `pervenstvo-oblasti-sredi-yunoshey` — «Первенство области среди юношей» | Регистрация: лимиты, очередь, исправления, документы M04 | +5 дней, 24.10 | REGISTRATION_OPEN |

Slug формирует API из названия. В таблице — значения на чистой БД без суффикса; точные ссылки всегда брать из вывода сида. При коллизии slug API добавляет окончание. Идемпотентность — по полному названию; изменение DEMO_DATE для уже созданного события требует сброса.

## Подготовка до появления зрителей

1. Проверить утверждённый main, HTTPS/health, мобильную сеть и резервную копию БД **и файлов документов**; выполнить чек-лист [репетиции](qa/rehearsal-2026-10-17.md). Запуск: [scripts/demo/README.md](../scripts/demo/README.md).
2. На выделенном демо-стенде выполнить `DEMO_DATE=2026-10-19 DEMO_EVENTS=A,B,C npx tsx seed.ts` из `scripts/demo`. Нужен полный сид. `--skip-import` подготавливает только настройки и не создаёт данные для этого сценария.
3. Сверить вывод: A — 160 заявок/96 пловцов, все заплывы FINISHED, 160 опубликованных результатов, 2 CORRECTED и 3 DNS/DNF; B — 200 заявок/120 пловцов, первые два заплыва сессии 1 FINISHED с результатами, остальные PUBLISHED; C — 124 заявки/124 пловца, из них 114 CONFIRMED, 6 NEEDS_CORRECTION, 4 WAITLISTED, два документа MEDICAL_CERT/PENDING. В C 120 заявок вне очереди **включают** шесть на исправлении. Во всех событиях 300 уникальных пловцов, ровно 40 общих B/C, 12 клубов; служебные профили в эти 300 не входят.
4. Открыть отдельные профили браузера: `org@flounder.demo`, `sec@flounder.demo`, `judge@flounder.demo`, `parent@flounder.demo`; зритель анонимно на телефоне. Пароли передаются через окружение/локальный `.env`, не показываются. Ведущий, родитель, секретарь, судья и ответственный за сервер назначаются до репетиции.
5. Подготовить вкладки C `/e/{slug}/register`, B `/e/{slug}/start-list` и `/live`, A `/e/{slug}/results`; кабинет организатора для каждого события. Подготовить `set-M.xlsx` и `set-M-with-errors.xlsx` из `docs/scripts/demo/out/`, сохранённые PDF и запись репетиции.
6. Для одного участника C владелец задаёт `DEMO_OWNER_EMAIL` в окружении/локальном `.env` (default `sergeymcdzkz@gmail.com`, отдельный аккаунт участника; адрес platform_admin `sergeymcdz@yandex.ru` не использовать): это аккаунт с паролем PARENT_PASSWORD (или DEMO_PASSWORD). В локальном прогоне почта выключена. На демо проверить SMTP и очередь M05 заранее; показывать письмо из заранее открытого ящика владельца, не обещать доставку без проверки. Другие созданные сидом аккаунты используют `@flounder.demo`; импортированные профили не имеют e-mail/аккаунта.
7. Два файла документов — вымышленные PDF с явной пометкой DEMO. Просмотр только из кабинета уполномоченного организатора; публичных ссылок на документы в сценарии нет. Включить секундомер, запись экрана и увеличить шрифт проектора.

Резерв: сохранённые PDF/видео и проверенный резервный стенд. При необходимости отдельной копии событий использовать `EVENT_TITLE_SUFFIX=" · резерв"` во всех командах seed/reset. Один повторный сид не возвращает изменённые в ходе демо заявки в исходное состояние — перед повтором сценария нужен reset выбранного события.

## Семь шагов

### 1. Три состояния и QR — 0:00–1:30, A → B → C

Организатор показывает три карточки: «Прошедший кубок уже с результатами, ближайший — с готовым стартовым протоколом, на первенство ещё можно подать заявку». Сверить названия, даты 11/20/24 октября и статусы из таблицы. На B показать бассейн 25 м/8 дорожек, две сессии и четыре вида 50/100 вольным стилем; на C — восемь видов 50/100/200/400 вольным стилем, лимит события 150 и по 16 на вид. QR C открывает карточку без входа.

### 2. Повторный импорт M — 1:30–3:30, B

В кабинете B уже **200 заявок**. Загрузить `set-M-with-errors.xlsx`: total=203, 200 обновлённых/пропущенных, три ошибки — строки 202 (31.02.2013), 203 (X-999), 204 (пустая фамилия). Затем исправленный `set-M.xlsx`: total=200, created=0, errors=[], всего остаётся 200, а не 400. Замерить время импорта, цель ≤10 с. Пояснить: регистрация закрыта для родителей, организатор может повторно импортировать тот же состав; готовые заплывы сохраняются. Не менять состав или времена в файле во время показа.

### 3. Заявка с телефона и лимиты — 3:30–5:30, C

Родитель входит `parent@…` и открывает C `/register` при ширине 375 px. Вымышленный участник: **Демов Тимофей**, 18.04.2014, М, «Дельфин»; выбрать **100 в/с 01:49.50 и 200 в/с 03:52.00**. На этих видах есть место; M-50 уже заполнен, его очередь показываем отдельно. Согласие, отправка → две SUBMITTED; организатор видит 126 заявок вместо 124 и подтверждает их. Бесплатная регистрация не списывает деньги; онлайн-платёж в этом шаге не выполняется.

### 4. Модерация, очередь, документы, письмо — 5:30–8:00, C

Включить фильтр NEEDS_CORRECTION: шесть заявок с причиной «уточните данные медицинской справки». Показать четыре WAITLISTED на M-50 и позиции очереди; не подтверждать их вручную ради демонстрации. Открыть документы двух участников: MEDICAL_CERT, PENDING, действительный демонстрационный PDF. Показать письмо в ящике владельца, если доставка проверена до показа. Реплика: «Документы доступны комиссии; родитель получает уведомление о своей заявке». Не менять статусы шести заготовленных заявок, чтобы сохранить пример.

### 5. Посев и опубликованный стартовый протокол — 8:00–9:30, B

Показать готовые заплывы B, полный/неполный, дорожки 4,5,3,6,2,7,1,8, NT после времён, группы 2014–2016, 2012–2013, 2010–2011. Валидатор — ERROR=0. Посев уже выполнен сидом: **не пересоздавать** опубликованные заплывы с результатами. Показать режим BY_AGE_GROUP и circleSeedTopHeats=false, расписание 10:00/15:00 Самара, estimatedEndsAt. Анонимно открыть стартовый протокол и серверный/печатный PDF.

### 6. Табло и ход соревнования — 9:30–11:00, B

Первые два заплыва сессии 1 уже завершены; открыть их результаты. На `/live` есть текущий третий и три следующих заплыва, поле «Отставание»; нулевое значение допустимо, поскольку дата B впереди дня демо. Судья открывает третий опубликованный заплыв и нажимает «Старт»; зритель видит обновление без reload ≤15 с. Секретарь показывает ввод результатов. При завершении этого заплыва: заполнить все дорожки → сохранить → опубликовать → «Финиш»; исходное состояние B после этого изменится, перед следующим показом потребуется сброс B.

### 7. Итоговый протокол и медалисты — 11:00–14:00, A

Анонимно открыть A `/results`: результаты всех 160 стартов, места 1/2/3 в абсолюте и возрастных группах, два CORRECTED с исправлением на 0.10 с, две DNS и одна DNF без места. Организатор показывает протокол результатов и PDF; судья имеет доступ к вводу, исправление опубликованных результатов выполняет секретарь/организатор. Объяснить, что A завершено, все его заплывы FINISHED и результаты уже опубликованы. Сравнить жизненный цикл C → B → A на трёх карточках.

## При сбое и после показа

На устранение сбоя — не более 20 секунд. Проверить список/результат до повторной отправки запроса. При недоступности API показать сохранённый отчёт/PDF/видео и вслух назвать переключение на резерв; SQL-правки в ходе показа не выполнять. Ошибки 500/console фиксировать, не выдавать резерв за успешный основной прогон.

После репетиции сохранить фактические времена, PDF, снимки и замечания. До следующего показа сбросить изменённые B/C по выбранным slug и повторить полный сид с **тем же DEMO_DATE=2026-10-19**; A не сбрасывать, если оно не менялось. Повторный сид без reset проверяет существующие данные и не маскирует расхождения. Проверьте телефоны Android/iOS и PWA отдельно: эмуляция браузера не заменяет физические устройства.
