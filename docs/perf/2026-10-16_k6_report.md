  `grafana/k6:0.54.0`, Caddy 2.11.7.
- Baseline: актуальный main `4571b33d5ed836d2cd39cc1d474dc89447cbadc1`;
  API image `sha256:a6943b23c7fc0899f25166598d79738d1979ff6144d480c8d92fbea388633720`.
- После A1–A8: API image `sha256:cb4bcca05409b8c6b08ba7c48cda3aa45e825b98a4d00f3778269d1000c2c55e`.
- Использован `infra/compose.prod.yaml`: baseline из main, затем версия S03 A,
  одна и та же локальная БД. Временный override публикует только loopback-порт
  API 8080; SQL DEBUG включался отдельно для подсчёта запросов, в k6 — WARN.
  Образы API собраны из Maven jar вне Docker, runtime повторяет production
  (тот же `eclipse-temurin:21-jre`, curl, non-root app, `/data/files`). Это обход

- Фикстура создана штатным `scripts/demo/seed.ts` через HTTP: 200 заявок, 120
  импортированных профилей, 4 дисциплины, 31 заплыв. Через штатные API выполнены
  посев, расписание, публикация заплывов, ввод и публикация результатов.
  Событие `3f3efd37-785f-4b1e-9a5c-8dc38c5e29a6`, вид `3150b426-ceb5-4805-92da-bf3ef6c333cb`,
  slug `otkrytyy-kubok-samary-po-plavaniyu-demo`. В измеряемом виде 8 заплывов.
- Перед каждой финальной парой public/organizer прогреты все 13 GET (20 кругов), затем
  сценарии запускались последовательно по 2 минуты. Сборки и тесты параллельно
  финальным k6-прогонам не выполнялись. Пробные прогоны в таблицы не включены.
- Public: 50 RPS суммарно, равномерно по 6 URL; organizer: 10 RPS по 7 URL,
  один вход в setup. Логин не входит в строки URL ниже; глобальный threshold k6

  полные JSON 200. Экономия трафика от ETag/304 проверена интеграционными тестами.

## SQL: устранение N+1

| Операция | main: всего / SELECT | S03 A: всего / SELECT |
|---|---:|---:|
| `protocol` | 164 / 164 | 10 / 10 |
| `save-and-rank` | 198 / 100 | 46 / 46 |

Подсчёт строк `org.hibernate.SQL` сделан на локальном API с DEBUG, отдельно
для X-Request-Id каждого запроса, включая JWT/RBAC и обогащение профилями.
GET — результаты вида с 8 заплывами; POST — сохранение тех же времён 6 дорожек
первого заплыва, включающее `rankDiscipline`. При построчном ранжировании до
изменений Hibernate выполнял промежуточные UPDATE мест перед очередными SELECT;
пакетная загрузка убирает промежуточные чтения и flush.
JSON обоих ответов до/после совпадает после нормализации порядка массивов; все значения, группы и места сохранены.

`RegistrationLookup.findByIdIn` уже присутствовал в актуальном main; использован
существующий межмодульный интерфейс. Фактический метод чтения называется `protocol`.
Новый тест проверяет одинаковое число SQL для 2 и 50 дорожек (8 заплывов);
существующие ожидания результатов/мест не изменены.

## Рестарт и прокси

**12.55 с**, включая остановку/запуск контейнера, опрос раз в секунду
(цель ≤ 90 с). Старт приложения из лога: `Started SportPlatformApplication in 10.673 seconds (process running for 11.138)`.
Проверка выполнена напрямую через локальный API.

Caddyfile прошёл `caddy validate`. В отдельном локальном контейнере с недоступным
API после повторов reverse_proxy вернул HTTP 503, `Content-Type: text/html; charset=utf-8`,
`Retry-After: 30` и страницу «SportGate — технические работы».
Это отдельная проверка ошибки, не замер внешнего HTTPS/TLS VPS.

Все значения относятся к прямым GET API на локальном стенде. Shallow ETag
вычисляется по уже сформированному телу; conditional GET экономит трафик,
а max-age позволяет браузеру пять секунд обходиться без запроса к серверу.
У лёгких GET организатора p95 вырос на 0,9–2,5 мс при сохранении запаса до
500 мс; один прогон не позволяет отделить влияние настроек от шума измерения.

- Все final k6 thresholds пройдены (в том числе по каждому URL): public p95 < 300 мс,
  organizer p95 < 500 мс, ошибок 0 %, пропущенных итераций 0.
- Полный `mvn -q test`: **1625 тестов, 0 failures/errors/skipped, exit 0**.
  Отдельный прогон imports/scheduling/modulith/notifications
  с batch_size=50, order_inserts/order_updates=true и completion-mode=delete.
  Modulith 1.4.1 поддерживает DELETE (проверены enum и поведение тестов).
- Frontend: 3 node-теста и 159 Vitest-тестов; `npm run build` и `npm run lint`
  проходят. Lint имеет существующие предупреждения в неизменённых файлах.
  PWA precache — 93 entries / 748,17 KiB; интервалы опроса не менялись.
- ETag/304 и Cache-Control проверены для 6 JSON URL и каталога. PDF и подписанные
  документы сохраняют no-store без ETag. Проверено сохранение X-Flounder-Cached
  при JSON 200 с ETag (модель ответа fetch после HTTP revalidation/Workbox);
  браузерные E2E в этот прогон не включались.
- Дополнительно публичные start-list/results PDF сформированы в реальном
  контейнере с новыми JVM-лимитами: 131380/180285 байт, HTTP 200, no-store, без ETag.
- `docker compose … config --quiet`, `caddy validate`, чистая миграция Testcontainers
  проходят. Запросы к production и деплой на VPS не выполнялись.

В конце полного прогона Surefire завершил fork JVM после 30-секундного ожидания
shutdown hook (Maven exit 0, XML-результаты выше). Дамп показывает ожидание
`JpaEventPublicationRepository.findIncompletePublications` / Hikari в
`SpringApplicationShutdownHook`; такой же стек есть в сохранённом дампе исходного
окружения от 12.10.2026. Эта особенность завершения тестового процесса не менялась.
Локальный production-контейнер отдельно штатно перезапущен за 12,55 с.

Цели, которые нельзя переносить на целевой VPS без повторного замера: абсолютные
p95, CPU/RSS и время рестарта на 2 vCPU / 4 ГБ. Локальные результаты и лимиты
приведены выше; внешний TLS, SPA и SMTP-сервер в нагрузочном профиле не участвуют.
