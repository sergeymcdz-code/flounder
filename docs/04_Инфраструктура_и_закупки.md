## 3. Мощности: расчёт под 50 соревнований
Нагрузка: событие на 1 000 участников = ~1 000 заявок, ~150 заплывов, ~1 000 результатов; в день старта — до 1 000 зрителей табло, обновление каждые 15 с → ~70 запросов/с на кэшируемые публичные эндпоинты (p95 < 50 мс из кэша). PostgreSQL на весь сезон (50 событий) — < 1 ГБ данных. Один сервер 4 vCPU / 8 ГБ с запасом ×5 покрывает это; второй сервер нужен только для отказоустойчивости (этап 4). Вертикальное масштабирование Timeweb — без переезда.

## 4. Доступы, которые нужны Claude

- Логи стенда — по запросу через вас (команда в runbook) или read-only SSH-пользователь (необязательно).
