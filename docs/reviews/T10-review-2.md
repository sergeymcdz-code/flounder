## Новые замечания

**Н1 (обязательно).** `bodies.ts:21–24` / `seed.ts:54`: `venueMeta` отправляется только при `REQUIRE_VENUE_META=true`; по умолчанию (`.env.example:11` — `false`, README `:53` — «до обновления T01 оставьте false») площадка создаётся **без** метаданных. Но T01 уже принимает поле (`origin/feat/T01-blockers` `3e2443a`: `CreateVenueRequest.venueMeta`, `VenueResponse.venueMeta`, `VenueMapper`, `VenueIntegrationTest.venueMetadataSurvivesCreateGetAndList`). Последствия на слитом `main`: первый запуск сида в режиме по умолчанию запишет `venue_meta = {}`; `reset.sql` площадку **сохраняет**, а строгий режим «для уже существующей площадки только проверяет» (`README:53`, `seed.ts:62`) — то есть после первого же запуска бассейн на демо навсегда без `courseLength`, публичная карточка без «25 м», и исправить это сидом нельзя. Обоснование «не отправлять неизвестное поле» неверно: `application.yml` не включает `fail-on-unknown-properties`, Spring Boot по умолчанию игнорирует неизвестные поля — отправка `venueMeta` на старом DTO безопасна (о чём и говорило первое ревью, блок. 2). Правка: `venueBody()` всегда включает `venueMeta: {lanes: 8, courseLength: 25}`; `REQUIRE_VENUE_META` управляет только тем, падать или предупреждать при отсутствии поля в ответе. Соответственно поправить тесты `bodies.test.ts:20–25`, `seed.test.ts:134` (ожидание `not.toHaveProperty('venueMeta')`) и `FakeApi` (см. Н2), README `:51–53`, `.env.example:10–11`, demo-script `:18`, «Вопросы для согласования» п.1 (`:117`) — T01 доработан, вопрос снять.

**Н2 (желательно).** `seed.test.ts:20–23`: `FakeApi` отвергает неизвестные поля `POST /venues` кодом `request.unknown_field` — такого поведения у бэкенда нет (см. Н1), и именно эта «строгость» закрепила неверное решение. Заменить на модель реального контракта: неизвестные поля игнорируются; `supportsVenueMeta=false` → `GET /venues/{id}` без `venueMeta` (старый T01), `true` → эхо сохранённого объекта (`3e2443a`).

**Н3 (желательно).** `seed.ts:62–63`: текст ошибки строгого режима «Требуется доработка T01» устареет после слияния `3e2443a`; реальная причина на слитом `main` — площадка ранее создана без метаданных. Сообщение: «площадка `<имя>` сохранена без venueMeta {lanes:8, courseLength:25}; API обновления площадки нет — задайте параметры в БД или создайте площадку заново».

**Н4 (мелочь).** `demo-script.md:24` — реплика шага 1 выросла примерно на 15 с (три новых предложения), при лимите шага 1:30 это заметно; «Показать» `:26` просит открыть форму с пресетом и флагом, т.е. ещё переход. Либо сократить реплику до одной фразы («группы — пресетом, круговой посев — флагом, расчётный конец сессии покажем после посева»), либо отдать 15 с из резерва шага 4 и отразить в таблице хронометража.

**Н5 (мелочь).** `README.md:72` обещает «URL подключения передаётся через `PGDATABASE`» — верно для libpq (connection string в `PGDATABASE` допустима), но стоит упомянуть, что при `postgresql://…` с паролем в URL пароль попадёт в окружение дочернего процесса; безопаснее `~/.pgpass`. Не блокирует.
