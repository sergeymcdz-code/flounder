## Блокирующие

1. **`ChangeRegistrationUseCase.java:138`** — безусловная `publisher.publishEvent(new RegistrationSubmittedEvent(id))` после `capacity.allocate`, который может поставить WAITLISTED. Это тот самый «обязательный семантический шаг» из ревью 2 («Порядок слияния», п. 2); Codex в описании PR («Ребейз после ревью 2») явно отложил его «до сообщения владельца задачи», merge-коммит координатора его не содержит, хотя заголовок утверждает обратное. Последствие: участник, вернувшийся в очередь после исправлений, получает письмо «Заявка подана» (M05 outbox), а при промоуте — ещё одно. Исправление:

   ```java
   // ChangeRegistrationUseCase.resubmit, вместо :138
   if (RegistrationStatus.SUBMITTED.name().equals(entity.getStatus()))
       publisher.publishEvent(new RegistrationSubmittedEvent(id));
   ```

   и в `M06LifecycleLimitsIntegrationTest.resubmissionReturnsToWaitlistWhenFreedPlaceHasAlreadyBeenTaken` после `:250`:

   ```java
   assertEquals(1, domainEvents.stream(com.acme.sportplatform.registrations.RegistrationSubmittedEvent.class)
           .filter(e -> e.registrationId().toString().equals(original.path("id").asText())).count());
   ```

   (ожидание: одно событие от первоначальной подачи, ноль от resubmit в очередь). Правка локальна, не затрагивает M04/M05/M08; CI должен остаться зелёным.
