## Расхождения с T06 (`origin/feat/T06-public-api` `a4be8a6`, `PublicResponses.java`, `PublicPublicationController.java`, `PublicPublicationService.java`)

Контракты в целом совпали: `Live.currentUnit/next[]` отдают `disciplineId, disciplineNumber, disciplineName, sequenceInSession, status, lanes[]` — ровно то, что фронт теперь использует в первую очередь; `/results` → `{disciplines[{id,number,name,overall[],byAgeGroup[{code,name,rows[]}]}]}`; `ResultRow {place,lastName,firstName,birthYear,club,display,timeMs,status}`; `CORRECTED → VALID`, `DID_NOT_* → DNS/DNF/DSQ` (`isValidResult` фронта принимает `VALID|OK`); `empty:true` только у пустых дорожек, у занятых `empty` опущен (`NON_NULL`); `athletes[].swims[].result` может быть `null`; пути и `?q=` совпадают. Остаются:

1. **`venue` может быть `null`** (`PublicPublicationService.java:40`: `event.venueName() == null ? null : new Venue(…)`), а фронт объявляет `venue: {…}` обязательным и обращается `event.venue.city` в `PublicLayout.tsx:113`, `EventPage.tsx:22,25`, `Protocol.tsx:20`, `event.venue.lanes` в `LivePage.tsx:287`, `HeatPage.tsx:32`, `StartListPage.tsx:38` → TypeError и белый экран для события без площадки. Также `Venue.courseLength` — `Integer` (nullable), `lanes` — `asInt(8)` (не null). Правка B: `venue: {…} | null`, `courseLength: number | null`, в UI — «Площадка не указана», число дорожек по умолчанию 8 (как на бэкенде).
2. `Heat` стартового протокола в T06 несёт `sequenceInSession: int` и `status: string` (`PublicResponses.Heat`); фронтовый `Heat` их не объявляет — безвредно, но можно добавить как `?`-поля и убрать дублирующую логику `LiveUnit`.
3. `OccupiedLane.display: string|null` (`00:32.15`/`NT`) — фронт форматирует `seedTimeMs` сам (`time()`); расхождения в формате нет, поле можно не добавлять.
4. `StartSession` имеет `startsAt: OffsetDateTime|null` и синтетическую сессию `{id:"unassigned", name:"Без сессии", startsAt:null}` для видов без сессии (`PublicPublicationService.java:65`) — фронт использует только `id/name`, рендерится корректно, тип можно дополнить `startsAt?: string | null`.
5. `Swim.lane` — `Integer` (nullable) против `lane: number` во фронтовом `AthleteMatch`; при `null` в карточке «Найти себя» будет «дорожка » пусто. Сделать `lane: number | null` и выводить «—».
6. `Discipline.gender/stroke` в T06 — сырые строки из `event_discipline` (`d.gender()`, `d.stroke()`), не нормализуются как в `ageGroupMatches` (`MALE/М → M`). Если T03/посев хранит `M/F/X` и `FREE/BACK/…` — совпадает; иначе фильтр `eligible()` в форме заявки и подписи стилей разъедутся. Замечание в T06-review-2 (нормализовать на бэкенде), фронт не менять.
7. `Live.currentUnit` при отсутствии активного заплыва — `null` (`JsonInclude.ALWAYS`) — фронт обрабатывает (`LivePage.tsx:107–112`). OK.
8. Описание `/live` в OpenAPI T06: «обновление из кэша не реже 10 секунд» против опроса 5 с — по ревью-1 TTL ≤ 3 с должен уйти в T06-review-2, во фронте менять нечего.

## Новые замечания (по коммиту 4319781)

- **A. Флаги моков рассинхронизированы** (см. п.3): `.env.demo`, `.env.example` → `VITE_API_MOCK`; `build:demo` удалить из `package.json` (или задокументировать как «только `dev:demo`»), в `vite.config.ts:118` `disable` оставить по `mode === 'demo'` (dev-only — это нормально, т.к. `vite build --mode demo` больше не нужен). - **B. `venue` nullable** — см. «Расхождения с T06» п.1. Небольшая правка типов + 6 мест использования.
