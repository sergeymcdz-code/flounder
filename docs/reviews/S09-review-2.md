## Желательные

1. **Фон рисуется дважды на каждой странице.** В новом `docs/qa/S09-samples/diploma.pdf` content-stream страницы содержит `/Im1 Do` два раза (прежний образец с `<img>` — один раз); `pdfimages -list` показывает два вхождения объекта 7. Вероятная причина — `.diploma { position:relative; z-index:0 }` (`diplomas.html:3`) создаёт слой, и openhtmltopdf красит его background и в потоке, и в слое. На размер PDF не влияет (XObject общий, тест это подтверждает), но для 200 страниц с фоном 8,7 Мпикс каждый просмотрщик/принтер растрирует фон 400 раз вместо 200. Проверить, убрав `position:relative; z-index:0` у `.diploma` (у `.content` оставить `position:relative`), и добавить в перф-тест ассерт «один `Do` изображения на страницу» (например, через `PDFStreamParser` подсчитать операторы `Do`).
2. **D03 и `canManage`.** В `pr/66` блок кнопок на «Результатах» обёрнут в `{canManage && …}` (судья видит только `JudgingHeatList`); при слиянии `AwardsPrintControls` и бейдж «Неофициальные результаты» тоже должны оказаться внутри `canManage`, иначе судья увидит кнопки, дающие 403. Сам бейдж (`OrganizerResultsPage.tsx:41`) в кабинете организатора несёт мало смысла (у D03 аналогичное предупреждение стоит на публичной странице) — можно заменить подписью «Печать награждения» или убрать.
3. **Осиротевший файл фона.** `PATCH {"diploma":{"backgroundFileKey":""}}` (`DiplomaSettingsService.apply:58-71`) только обнуляет ключ, старый объект остаётся в `files` до следующей загрузки (`uploadBackground:327` удаляет только при замене). Удалять старый ключ в `apply`, когда `merged.backgroundFileKey()==null && current.backgroundFileKey()!=null` (через `FileLookup.delete`, как в `uploadBackground`), либо оговорить.
4. **`OrganizerDiplomaPage.tsx:14-18`** — три `setState` в теле рендера; лучше свести к одному состоянию `{ source, form, dirty }` или к `useEffect` по `[event.id, event.settingsJson]` с проверкой `dirty` — семантика та же, меньше повторных рендеров.
5. **Корректность файла фона** теперь не проверяется при загрузке (`uploadBackground:301-316` читает только размеры): JPEG с валидным заголовком и битым телом будет принят, а при рендере openhtmltopdf молча пропустит изображение — грамоты выйдут без фона без ошибки. Это осознанный компромисс из ревью 1; можно добавить дешёвую проверку `reader.read(0, param.setSourceSubsampling(16,16,0,0))`.
6. Прочее из ревью 1, не вошедшее в список правок и не исправленное (по-прежнему желательно, не блокирует): `FileService.get` пишет `DOWNLOAD` в `file_access_log` при каждой пробной грамоте (ж. 3 ревью 1); номера отменённых заявок в `GET /bib-numbers` без пометки (ж. 5 — описано в PR, принято); бинарные образцы в Git (ж. 9).
