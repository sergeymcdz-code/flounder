## Желательные замечания

1. `e2e/qa05-demo.spec.ts` — один `test()` на 424 строки с семью `test.step` и глобальным состоянием (`event`, `heats`). Для диагностики это осознанно (шаги зависят друг от друга), но при падении в шаге 2 шаги 3–7 бегут на неконсистентных данных и дают каскад ложных красных. Минимум — после `blocked` в шаге 2 или 4 помечать последующие шаги `test.skip`-подобной записью в `steps[]` (`blocked: 'skipped after step N'`) вместо попытки выполнить их.
2. `e2e/qa05-setup.ts:19-24` — `globalSetup` запускает сид с `DEMO_SEED_ENABLED=true` по адресу из `QA05_API_URL` без каких-либо проверок. Защита сида (`scripts/demo/config.ts:9`) смотрит на `NODE_ENV`/`SPRING_PROFILES_ACTIVE` **локального** процесса, а не целевого стенда: `QA05_API_URL=https://sportgate.pro npm run e2e` создаст на демо-стенде событие «… · QA05 2026-…», 202 заявки, заплывы и результаты (сид и API-вызовы идут из Node без CORS; упадёт только фронтовая часть). Добавить в `qa05-setup.ts` отказ, если хост `QA05_API_URL` не `localhost`/`127.0.0.1`, кроме явного `QA05_ALLOW_REMOTE=1`, и строку об этом в README.
3. `e2e/qa05-support.ts:40-44` — проверка `break-inside: avoid` берёт `getComputedStyle` у `<article>` в print-media эмуляции, а не разбиение в самом PDF; это прокси-проверка (QA05 допускает «по тексту PDF или по CSS»), но при 8 страницах стартового PDF стоило бы хотя бы `pdf-parse`'ом убедиться, что ни одна строка «Заплыв N —» не оказалась последней на странице. Не блокер.
4. `qa05-demo.spec.ts:171,237,325,373` — в сообщениях soft-expect нет ID дефекта (есть только у `:196` и `:398`); при чтении `results.json`/trace непонятно, какой красный — «известный». Добавить `'QA05-02: …'` и т.д. во все шесть, чтобы при закрытии дефекта было ясно, какую проверку ждать зелёной.
5. `qa05-demo.spec.ts:80` — `getByRole('button', { name: 'Изменить' }).nth(2)` (третья кнопка «Изменить» = первый вид после двух сессий) — индексный селектор, развалится при любом изменении порядка/числа кнопок на странице «Сессии и виды». Лучше `locator('tr').filter({ hasText: 'M-50-FREE' }).getByRole('button', { name: 'Изменить' })`.
6. `OrganizerEntriesPage.tsx:246` (QA05-04) — после правки кнопка «Оплачено» есть у всех 200 импортированных `NOT_REQUIRED`-заявок. Для демо приемлемо (сценарий показывает отметку при нулевом взносе), но до MVP показывать её для `NOT_REQUIRED` только если `status === 'CONFIRMED'` и ещё лучше — с подписью «Отметить (взнос 0)». Записать как follow-up в QA01/T04, не менять сейчас.
