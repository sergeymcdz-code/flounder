## Блокирующие

**Б1. Плейсхолдеры учётных записей в инструкции к рискованной операции.** `docs/infra-hardening.md:5-7` объясняет, что `<ssh-user>` «для первого входа — административная, после `su -` — владелец `~/flounder`», и далее везде пишет `ssh <ssh-user>@SERVER_IP` → `su - <ssh-user>` (`:16,26`; `:51-52`; `:76-77`). Та же замена в `docs/qa/rehearsal-2026-10-17.md` («Вход: `ssh <ssh-user>@SERVER_IP`, затем `su - <ssh-user>`»). Для оператора, который в этот момент отключает root SSH, это двусмысленно; в теле PR Codex пишет однозначно (`ssh root@SERVER_IP` → `su - deploy`). Нужно два плейсхолдера: `<admin-user>` (или прямо `root`, это не секрет) для входа до hardening и `<ssh-user>`/`deploy` для непривилегированного. Там же sed-регрессия: `docs/09_HANDOFF…:7` «локально `/home/claude/flounder`» → `/home/<ssh-user>/flounder` — это путь локальной сессии Claude, не сервер; вернуть.

**Б2. Пароль демо в новом файле.** `infra/tests/csp-browser.spec.mts:36`: `process.env.QA05_PASSWORD ?? 'Demo2026!'`. SEC01 (#75) убирает все такие fallback из `e2e/*` (в `pr/75` в `e2e/` их уже нет). Новый файл не должен возвращать пароль в репозиторий: `const password = process.env.QA05_PASSWORD; if (!password) throw new Error('Задайте QA05_PASSWORD')`.
