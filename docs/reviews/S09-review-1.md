## Блокирующие

**Б1. Фон грамоты дублируется на каждую страницу — память при 200 грамотах.** `diplomas.html:9`: `<div class="diploma" th:each…><img class="background" th:src="${background}">` — `background` это `data:image/…;base64,` всего файла (`PrintFormService:86-92`, лимит 5 МБ → до 6,7 МБ base64). Thymeleaf пишет строку в HTML N раз, затем openhtmltopdf парсит её в Jsoup-DOM и W3C-DOM — ещё два экземпляра строк атрибутов. Для типичного фона A4 (JPEG 300 dpi ≈ 1–2 МБ → 1,4–2,7 МБ base64) и 200 грамот это 280–540 МБ только HTML-строки (в UTF-16 из-за кириллицы — ×2) плюс копии DOM → порядка 1–1,5 ГБ при лимите JVM 1 ГБ (`docs/02_ТЗ_демо.md` §6.4 / S03). Тест `twoHundredDiplomasRenderWithinTwentySeconds…` (`PrintFormsIntegrationTest:131-138`) использует `enabled()` без фона (`:25`), поэтому 117 мс ничего не говорят о реальном сценарии. Правка: (а) вставлять фон один раз — например `<style th:inline="text">.diploma{background-image:url("[[${background}]]");background-size:210mm 297mm;background-repeat:no-repeat}</style>` (или зарегистрировать в `PdfRenderer` `useProtocolsStreamImplementation(factory,"diploma-bg")` и ссылаться на `diploma-bg://background` — тогда base64 в HTML не нужен вовсе); (б) убедиться, что в PDF изображение встраивается одним XObject (кеш изображений openhtmltopdf по URI это обеспечивает), и добавить в перф-тест фон ~1,5 МБ (сгенерировать JPEG 2480×3508 с шумом), ассерты: ≤ 20 с, размер PDF < ~3× размера фона, 200 страниц; (в) снизить лимит пикселей фона с 25 Мпикс (`PrintFormService:131`) до ~12 Мпикс (A4 при 300 dpi = 8,7 Мпикс): PNG такого размера openhtmltopdf распаковывает в сырой растр (25 Мпикс × 3 байта = 75 МБ) при каждом рендере.

**Б2. Перебазирование после S05 и S06 (порядок слияния задан: S04 → S05 → S06 → S09).** `git merge-tree pr/64 pr/58`: конфликты в `events/api/PatchEventRequest.java` (S05 добавляет `payment` в ту же строку — оставить оба поля, как и предписано заданием), `events/application/UpdateEventUseCase.java` (конструктор + блок `fields.contains`) и TSV. `git merge-tree pr/61 pr/58`: `documents/infrastructure/PdfRenderer.java` (S06 ввёл `renderTemplate(String, Context)` + `renderStandings`, S09 — `render(String, Map)`; свести к одному общему методу и вызвать его из обоих), `documents/web/DocumentsController.java` (S06 добавил standings-эндпоинты, S09 сделал `response` статическим), `documents/package-info.java` (`allowedDependencies`: объединить `standings` + `scheduling`,`files`), TSV, а также фронт `App.tsx`/`OrganizerEventLayout.tsx` (обе ветки добавляют вкладку/маршрут). С `pr/60` (S04) конфликт только в `OrganizerHeatsPage.test.tsx` (`beforeEach`). Все конфликты механические, но после разрешения нужно перепрогнать `ModulithArchitectureTest`, `PrintFormsIntegrationTest`, `Qa04RoleMatrixIntegrationTest` и фронтовые тесты.

Либо помечать/убирать их в `list`, либо описать в PR («номер закрепляется за профилем до перенумерации»).
