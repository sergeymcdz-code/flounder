## Блокирующие

**Б1. `delaySec` сессии без фактов старта = 0 вместо `null`** (`sport-platform/src/main/java/com/acme/sportplatform/analytics/infrastructure/AnalyticsReadRepository.java:111-113`, `:207`). `greatest(0, max(...))` в PostgreSQL возвращает 0, когда `max` = NULL (GREATEST игнорирует NULL), а `num()` не допускает NULL. В результате каждая сессия, у которой ни один заплыв ещё не стартовал (а это все сессии до дня соревнования и все будущие сессии в день старта), отдаёт `delaySec: 0`, таблица «Загрузка сессий» показывает «0» в колонке «Отставание, сек», а XLSX — число 0. Задание: «заплывы без факта старта не учитываются (план не подставляется)»; фронт готов к `null` (`s.delaySec ?? '—'`, `AnalyticsPages.tsx:86`), и прежний контракт/тест M08 отдавал `null`. Codex вместо этого переписал ожидание теста на `==0` и зафиксировал «При отсутствии измерений — 0» в `docs/analytics/M08-analytics.md:34`. Правка: SQL `case when max(...) is null then null else greatest(0, max(...)) end` (или `nullif`-эквивалент), nullable helper для `delay_sec` (по образцу `decimal()`), вернуть `allMatch(s -> s.delaySec()==null)` в `AnalyticsIntegrationTest` для фикстуры без стартов, оставить 420/0 в тестах с фактами; строку в `M08-analytics.md` — «при отсутствии фактов старта — null (на панели “—”)».
