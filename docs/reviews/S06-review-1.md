## Блокирующие

**Б1. Публичный `standings.pdf` без серверного кеша.** `DocumentsController.java:60-63` → `DocumentService.publicStandings:36-39` вызывает `renderer.renderStandings` на каждый запрос; `PublicDocumentService.get` (results/start-list) для той же ситуации кеширует `PdfDocument` в `publicPdfCache` (Caffeine 60 с, `DocumentsConfig.java:16`) и перепроверяет видимость на каждом хите. Так как `PdfRenderer` ограничен `Semaphore(2)` с ожиданием 10 с (`PdfRenderer.java:26,53`), серия анонимных запросов к публичной ссылке «Скачать PDF» (она на странице `/e/:slug/standings` и индексируется) переводит и организаторские `results.pdf`/`start-list.pdf`/`standings.pdf` в 503 `documents.busy`. Правка: в `PublicDocumentService` добавить `standings(slug)` — `events.getPublicBySlug(slug)` (видимость), затем `cache.get(slug + ":" + event.id() + ":standings", k -> documents.publicStandings(slug))`; `DocumentsController.publicStandings` вызывать его. Проверка видимости/публикации остаётся внутри `documents.publicStandings` (через `StandingsLookup.publicBySlug`), поэтому после снятия публикации кеш не отдаст PDF дольше 60 с — это допустимо для results.pdf сегодня, но лучше включить в ключ `config`-часть: проще всего не кешировать при 404 (исключение и так не кешируется Caffeine), а при отзыве публикации принять задержку ≤60 с и отметить в PR. Тест: в `StandingsSecurityIntegrationTest` два подряд GET `/standings.pdf` → один вызов рендера (по образцу теста кеша M03, `PublicDocumentServiceTest`).

## Желательные

1. **Вызов `StandingsLookup.publicBySlug` в `DocumentService.publicStandings` + повторный `getPublicBySlug`** (`DocumentService.java:36-39`): событие ищется дважды (внутри `publicBySlug` и ещё раз для id). Можно вернуть из `StandingsLookup` id события или принимать его из `PublicDocumentService` после Б1.
2. **Кнопка PDF на публичной странице** (`StandingsPage.tsx:24`): `<a href>` на API вместо `PdfDownloadButton` (как `ResultsPage.tsx:25-27`) — при 503 `documents.busy`/404 пользователь увидит JSON ошибки в новой вкладке, а не русское сообщение; имя файла задаётся сервером (`Зачёт-<slug>.pdf`), это ок. Если оставить ссылку — добавить `download` и `rel="noopener"`.
3. **Опрос зачёта на всех публичных страницах** (`PublicLayout.tsx:51-52`): `usePublicData(loadStandings, 30_000)` шлёт `GET …/standings` каждые 30 с с каждой открытой публичной страницы (включая `/live`, где уже есть опрос раз в 5 с), в том числе когда зачёт не включён (404 → запрос к БД `events`+`event_standings_configs` без кеша). Задание просило «один дополнительный запрос». Предложение: без `pollMs` (запрос один раз на slug) либо опрашивать только на странице `/standings`; при 404 ссылка и так скрывается при следующей навигации.
4. **Breakdown и лимит** (`StandingsCalculator.java:65-69`): результаты, отсечённые `maxScoredPerClubPerDiscipline`, в «Из чего сложилось» не показываются — организатор не увидит, почему у клуба «зачтено 4 из 6». Можно отдавать их с `points=0` и флагом `counted=false` (или отдельным списком).
