## Желательные

- **Ж1. `frontend/e2e/qa05-demo.spec.ts:187-201`.** D03 в main сделал цикл оплаты у секретаря строгим (`click` → `expect(... 'Оплачено').toHaveCount(0)` без условий). Ребейз вернул форму S05: `if (await sec.getByLabel('Поиск').count())` / `if (await row.getByRole('button', …).count())` и fallback `api(sec, …/mark-paid, 'POST')` с комментарием «the failed UI assertions remain red» — хотя внутри цикла падающих UI-ассертов больше нет. Благодаря жёсткому `toHaveCount(2)` на `:185` fallback практически недостижим, поэтому не блокирую; но проще убрать обе проверки `count()` и строку `:200-201`, оставив клик → диалог → бейдж, как в main. Также подпись soft-ассерта на `:181` вернулась к «QA05: zero-fee mark-paid action» вместо «D03: confirmed zero-fee entries can be marked paid» — косметика.
- **Ж2. `frontend/src/features/organizer/OrganizerEntriesPage.tsx:296-297`.** В main для `CONFIRMED` с `paymentStatus === 'PAID'` в основном слоте действий была кнопка «Снять»; теперь основной слот для `CONFIRMED` пуст (условие `['PAID', 'ADMITTED'].includes(r.status)`), «Снять» остаётся только в меню «Ещё ▾» (`:302`). Функция не потеряна (тест main `offers payment…` проверяет именно `details`), но для CONFIRMED+PAID/WAIVED логично вернуть «Снять» в основной слот: `['PAID','ADMITTED'].includes(r.status) || r.status === 'CONFIRMED' && ['PAID','WAIVED'].includes(r.paymentStatus)`. Дополнительно: на странице теперь два фильтра по оплате — быстрый сегмент D03 `?payment=PENDING` (`:123,164`) и селект S05 «Статус оплаты» (`:175`); работают независимо (AND), стоит свести к одному источнику в follow-up.
