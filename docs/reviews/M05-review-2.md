## Желательные (не держат слияние)

1. **Фикстура QA04 коммитится в общую БД.** `commitQueue()` (`NotificationIntegrationTest.java:56-58`) делает `TestTransaction.flagForCommit(); end(); start()` — вместе с outbox коммитятся venues/users/organizations/events/registrations фикстуры `Qa04SecurityFixture`; `@AfterEach clearCommittedQueue` (`:59-62`) чистит только `notification_outbox`. Id/slug/email случайные, CI зелёный, но после каждого из ~10 таких тестов в контейнере остаётся событие `qa04-<uuid>` со статусом фикстуры — тесты, считающие публичные события/пользователей, могут стать зависимыми от порядка. Проще добавить в `@AfterEach` `delete from events where id=?`/`users …` (каскады) либо удалять по `ids`.
2. **`TZ` на стенде.** Дата письма берётся из `ZoneId.systemDefault()`; `compose.prod.yaml:62` уже прокидывает `TZ: ${TZ:-Europe/Samara}` в api — на стенде всё в порядке, но при локальном запуске/в CI (UTC) дата события у полуночи по Самаре сдвинется на день. Не код — просто помнить при ручной проверке.
3. `.env.prod.example:51,55` — `MAIL_PORT=`/`MAIL_ENABLED=` пустые: для compose это безопасно (`${MAIL_PORT:-587}`), но при локальном запуске с экспортом пустого `MAIL_PORT` Spring-плейсхолдер `${MAIL_PORT:587}` подставит `""` → `int port` не сбиндится и приложение не стартует. Лучше в примере дать `MAIL_PORT=587` и `MAIL_ENABLED=false` явно.
4. `@Primary` на `OutboxMailSender` больше не нужен (бин один) — можно снять, чтобы не маскировать будущий дубль; `assertOwner()` по-прежнему отвечает 404 на несуществующую организацию до проверки доступа (жел. 5 из ревью 1).
5. Исключение из `sent()`/`failed()` (сбой БД) прерывает оставшуюся часть батча (`sendBatch()` не ловит `DataAccessException`, тест это фиксирует) — для `@Scheduled` это лишь запись в лог и повтор через 10 с, приемлемо; можно ловить per-row и продолжать.
