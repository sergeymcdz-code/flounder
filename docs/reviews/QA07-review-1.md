## Блокирующие

**Б1. Покрыть п.1в (M02) и обновить утверждения «M02/M09 OPEN».** Задание: «если к моменту работы в main уже слиты M02/M09… — ребейзнись и покрой их тоже». M02 `9be55d9` и M09 `5e5259f` в main. Нужен e2e на изолированном пользователе: (а) смена пароля самим пользователем через `/password` (PasswordPage из M02): старый пароль 401, новый входит; (б) 429 после `APP_AUTH_LOGIN_MAX_FAILURES` (по умолчанию 5) неверных попыток, заголовок `Retry-After` > 0 и сообщение «Слишком много попыток…» на /login; (в) refresh при истёкшем access — сессия в sessionStorage содержит `refreshToken`; можно подменить `accessToken` на заведомо истёкший/невалидный и проверить, что `apiFetch` прозрачно обновил сессию без редиректа на /login. Внимание: лимитер считает и по IP (`LoginAttemptLimiter`: ключи `email:` и `ip:`, окно 15 мин) — тест 429 должен идти **последним** в прогоне и на отдельном email, иначе он заблокирует admin-часть и QA05 при повторных запусках с одного хоста; в README QA07 это оговорить. В отчёте и чек-листе заменить «M02/M09/D01 OPEN» на фактическое состояние main.

**Б2. Чек-лист: сброс основного события — процедура не соответствует `reset.ts`.** Чек-лист просит «сохранить проверенный SQL из вывода в `/tmp/rehearsal-main-reset.sql`» и выполнить `psql … < /tmp/rehearsal-main-reset.sql`. Но `reset.ts` без `--apply` **не печатает SQL** — он печатает готовую команду `psql "$DEMO_DATABASE_URL" -v ON_ERROR_STOP=1 -v demo_event_id=<uuid> -v demo_event_title='<title>' -f reset.sql` (`scripts/demo/reset.ts:46`), а `scripts/demo/reset.sql` использует psql-переменные `:'demo_event_id'`/`:'demo_event_title'`. Оператор 17.10 либо не найдёт, что сохранять, либо получит ошибку `syntax error` на переменных. Корректная серверная форма (без Node и без `DEMO_DATABASE_URL` в argv):
```bash
docker exec -i flounder-postgres psql -X -U sport_user -d sport_platform -v ON_ERROR_STOP=1 \
  -v demo_event_id='<uuid из вывода reset.ts>' \
  -v demo_event_title='<точное название из вывода reset.ts>' \
  < /home/<ssh-user>/flounder/scripts/demo/reset.sql
```
То же для резерва (название с « · резерв»). Остановка `api` перед SQL не обязательна (reset.sql — одна транзакция с `for update`), но допустима; тогда убрать абзац про «не копировать shell-префикс psql -c внутрь SQL-файла».

**Б3. Чек-лист: `docker run … node:22-alpine` без `-e HOME=/tmp` — `npm ci` упадёт.** Все три `docker run` запускаются с `--user "$(id -u):$(id -g)"`; у такого UID в образе нет home, npm пишет кеш в `/.npm` → `EACCES`. (`npx tsx` во втором/третьем вызове тоже нуждается в HOME для кеша npx.)
