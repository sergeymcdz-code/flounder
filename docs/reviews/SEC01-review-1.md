## Желательные

1. **`config.ts:17-22` проверяет все переменные окружения `*_PASSWORD`**, а не только свои (`ADMIN/DEMO/ORG/SEC/JUDGE/PARENT/OTHER_PASSWORD`). На машине разработчика с экспортированным, например, `POSTGRES_PASSWORD=sport_pass` (10 символов) сид откажет с сообщением про «опубликованный пароль», что собьёт с толку. В контейнере staging (`deploy-staging.sh:56-59`) передаются только три нужных `-e`, поэтому стенд не затронут. Предложение: белый список имён; для пустого значения — отдельный текст («не задан»), а не «опубликованный пароль запрещён».
2. **Имя `*IT` + явный include в surefire** (`pom.xml:231`): при `mvn verify` failsafe по умолчанию тоже подхватывает `**/*IT.java`, и класс прогонится дважды (CI делает только `mvn test`, поэтому сейчас не видно). Имя задано заданием; варианты — добавить `<excludes>**/LegacySeedAdminDisabledIT.java</excludes>` в failsafe или согласовать переименование в `LegacySeedAdminDisabledTest` и убрать include.
3. **`frontend/e2e/QA05-README.md:27`** не обновлён: теперь `qa05-setup.ts`/`qa07-setup.ts` требуют `ADMIN_EMAIL`, `ADMIN_PASSWORD` и `QA05_PASSWORD`/`DEMO_PASSWORD` из окружения (`credentials.ts`), иначе падают до запуска сида. Дописать одну строку.
4. **`docs/migrations/V020__seed_fixes.sql:3,9`** — это документальная копия, не Flyway-миграция (`sport-platform/README.md:243` называет её источником), запрет на редактирование старых миграций на неё не распространяется. Можно убрать пароль из комментария, оставив «исторический seed-администратор», чтобы приёмочный `grep` давал только тесты.
5. **Контрольная проверка в `deploy-staging.sh`** расходует одну неудачную попытку входа для `admin@flounder.demo` (лимит 5 за 15 минут на email, `LoginAttemptLimiter`). При нескольких деплоях подряд в 15-минутном окне шестая попытка вернёт 429 → деплой остановится с сообщением «должен вернуть 401 (получен 429)». Либо считать 429 допустимым (аккаунт всё равно недоступен), либо упомянуть в сообщении. После SEC04 (блокировка по email+IP) поведение изменится — согласовать там.
