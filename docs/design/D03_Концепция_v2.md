# D03 — Концепция интерфейса v2: «спортивный, уверенный, быстрый»

Дата: 15.10.2026 (ночь). Автор: продуктовый дизайнер (агент волны 5). Для кого: Сергей (владелец), координатор волны, Codex (задание `tasks/D03_UX_и_визуал_до_демо.md`). Основания: UX-аудит `D03_UX_аудит_2026-10-15.md` (ТОП-15, целевая ИА §4), исследование `docs/research/2026-10-15_process_and_competitors.md` (§4 паттерны, §5 приоритет D), концепция `D01_Концепция.md` + D02, ADR `docs/decisions/2026-10-13-d01-cveta-i-tema.md`, снимки `docs/design/screenshots/*.png`, CSS `frontend/src/styles/globals.css`, `components.css`, модули страниц.

Главная мысль: **D01/D02 дали продукту правильную палитру и шрифты, но не дали «скелета»** — у кабинета нет единой шапки, бокового меню по ролям, карточки соревнования как центра управления и единых компонентов (кнопка, бейдж, таблица, пустое состояние, подтверждение). Из-за этого каждый экран собран из своих CSS-модулей со своими кнопками и своими словами. v2 не перерисовывает экраны — она добавляет **систему компонентов и навигацию поверх существующей разметки**, а экраны меняются точечно по ТОП-15. Всё, что описано ниже, реализуемо Codex за сутки, если идти по приоритетам задания (must → should).

Рамки: без переписывания страниц с нуля; без миграций; API и контракты §5 ТЗ не меняются (единственное серверное исключение — проверка документов, см. задание); тексты на русском; бренд SportGate (S01) не трогаем — только используем.

## 1. Направление: три принципа

| Принцип | Что это значит в интерфейсе | Где уже есть (D01/D02) | Чего не хватает (v2) |
|---|---|---|---|
| **Спортивный** | Графитовая линейка, Oswald в заголовках и номерах, плотные табличные цифры, статус-бейджи как на табло | Шапка публичных страниц, протокол, табло, панель судьи | Кабинет организатора выглядит как «админка на Bootstrap»: светлые скруглённые карточки, одинаковые серые кнопки, нет ритма |
| **Уверенный** | На экране одно главное действие; у действия есть последствие («Опубликовать — 46 заплывов увидят все»); статусы называются одинаково везде; после действия — подтверждение «готово» | Правило «один primary» на публичных страницах | В кабинете 3–6 равнозначных кнопок в ряд; подтверждения универсальные; словарь статусов разный на разных экранах |
| **Быстрый** | Клики до действия ≤ 2 (см. аудит §1); «ведущая рука» — чек-лист; sticky-шапки таблиц; клавиатура у судьи; ничего не скрыто за UUID-формами | Ввод времени у судьи, Enter/Tab, маска | После входа — не в кабинет; судья — 4 действия до заплыва; «Заявки» в шапке = форма UUID |

Образ: **стартовый протокол на стене бассейна, переведённый в экран.** Чёрные линейки, крупные номера, белая бумага, одна цветная отметка — там, где действительно важно (LIVE, DSQ, ошибка).

## 2. Сетка и ритм

- **Единица ритма — 4 px**, шкала отступов D01 сохраняется: 4 / 8 / 12 / 16 / 20 / 24 / 32, добавляется `--space-10: 40px` и `--space-12: 48px` для секций.
- **Кабинет (≥ 1024 px):** `grid-template-columns: 232px minmax(0, 1fr)`; боковое меню `position: sticky; top: 56px`; рабочая область с `padding: 24px 32px`, максимальная ширина контента **1280 px** (таблицы заявок/заплывов — без ограничения ширины, `max-width: none`, иначе 13 колонок ломаются; снять правило `.page-content section { max-width: 760px }` для `/organizer/**`).
- **Кабинет (768–1023 px):** меню сворачивается в горизонтальную строку ссылок под шапкой (`overflow-x: auto`), контент на всю ширину.
- **Телефон (< 768 px):** одна колонка, `padding: 16px`; таблицы прокручиваются внутри своего контейнера (как в D02 для админки); первичная кнопка на всю ширину; вкладки события — горизонтальный скролл с тенью-подсказкой справа.
- **Публичные страницы:** как в D01 (`max-width: 960px`, нижняя панель), без изменений сетки.
- **Высота шапки — 56 px** везде (сейчас у кабинета ~72 px, у публичных ~64 px). Высота строки таблицы по умолчанию — 44 px (`compact` — 36 px, только для протокола/заплывов).

## 4. Токены v2 (расширение D01, `globals.css :root`)

Палитра D01/D02 и правило «один цвет — одно значение» **не меняются**. Добавляются токены поверхностей, границ, теней, радиусов, фокуса и размеров — чтобы компоненты не держали значения в своих модулях.

```css
:root {
  /* поверхности */
  --surface-page: var(--color-page);          /* фон приложения */
  --surface-1: var(--color-surface);          /* карточка, таблица, шапка */
  --surface-2: var(--color-surface-muted);    /* зебра, фон th, свернутые блоки */
  --surface-3: var(--color-primary-soft);     /* выделенная строка, активная вкладка, hover строки */
  --surface-sidebar: var(--color-surface);
  --surface-overlay: rgb(24 33 38 / 0.48);    /* подложка dialog::backdrop */
  /* границы */
  --border-subtle: var(--color-border);       /* карточки, разделители */
  --border-strong: var(--color-border-strong);/* поля ввода, ghost-кнопки */
  --border-rule: var(--color-text);           /* спортивная линейка 3 px под шапкой карточки, над заплывом */
  --border-width-rule: 3px;
  /* тени (только для всплывающего) */
  --shadow-card: none;
  --shadow-pop: 0 4px 12px rgb(24 33 38 / 0.12);
  --shadow-sticky: 0 1px 0 var(--color-border);          /* низ sticky-шапки таблицы */
  --shadow-drawer: -8px 0 24px rgb(24 33 38 / 0.16);
  /* радиусы */
  --radius-sm: 3px;   /* бейджи, кнопки */
  --radius-md: 5px;   /* поля ввода */
  --radius-lg: 8px;   /* карточки, диалоги */
  --radius-pill: 999px; /* индикатор-счётчик во вкладке */
  /* фокус */
  --focus-ring: 0 0 0 3px var(--color-surface), 0 0 0 5px var(--color-focus); /* двойное кольцо: видно и на графите */
  --focus-ring-inset: inset 0 0 0 2px var(--color-focus);                       /* для ячеек таблицы и строк */
  /* размеры */
  --control-h: 44px;       /* кнопки, поля (D01) */
  --control-h-sm: 36px;    /* компактные кнопки в строках таблицы, сегменты */
  --control-h-lg: 56px;    /* ввод времени у судьи, primary на 375 */
  --header-h: 56px;
  --sidebar-w: 232px;
  --content-max: 1280px;
  /* z-index */
  --z-sticky: 10; --z-header: 20; --z-drawer: 30; --z-dialog: 40; --z-toast: 50;
  /* движение */
  --motion-fast: 120ms; --motion-base: 200ms; --ease: cubic-bezier(.2,.0,.0,1);
}
```

Тёмная тема (`[data-theme="dark"]`) получает те же токены автоматически, потому что они ссылаются на `--color-*`; отдельно переопределить только `--surface-overlay: rgb(0 0 0 / 0.6)` и `--shadow-pop: 0 4px 16px rgb(0 0 0 / 0.5)`. Print: `--border-rule` → `#000`, тени → `none` (уже есть сброс D01).

Семантика тонов бейджей (новые алиасы, сверху существующих `--status-*`):

| Тон | Текст / фон | Значения |
|---|---|---|
| `neutral` | text-muted / surface-2 | Черновик, Снята, Архив, DNS, DNF, Без оплаты, «нет документа» |
| `info` | primary / primary-soft | Опубликовано (событие), В расписании, На рассмотрении, На проверке, Ожидает оплаты |
| `success` | success / success-soft | Подтверждена, Оплачена, Допущена, Принят (документ), Опубликован (протокол/результаты), Завершён |
| `warning` | warning / warning-soft | Лист ожидания, На исправлении, исправлено (CORRECTED), «не хватает» в чек-листе |
| `danger` | danger / danger-soft | **Только:** LIVE / Идёт (заплыв, соревнование), DSQ, Отклонена/Отклонён, Отменена, ошибка |

Это согласовано с ADR: красный — опасность/нарушение и LIVE. «Опубликовано» для события остаётся success (так в D01), для протокола/результатов — тоже success; info — для «в процессе, ждёт действия».

### 5.4 Чек-лист соревнования `EventChecklist` (7 шагов) — главная компонента v2

Размещение: первая карточка вкладки «Главная». Вычисляется из `EventContext` без новых запросов.

```
┌ Что дальше ──────────────────────────────────────────────────────────┐
│ ✓ 1  Программа                 4 вида · 2 сессии          Открыть →  │
│ ✓ 2  Регистрация открыта       до 13.10 09:00 · лимит 120/150        │
│ ●  3  Заявки                    202 · 2 на рассмотрении   Проверить →│
│ ○  4  Заплывы сформированы      0 из 4 видов         Сформировать → │
│ ○  5  Стартовый протокол        не опубликован                       │
│ ○  6  Результаты                0 из 46 заплывов                     │
│ ○  7  Соревнование завершено                                         │
└──────────────────────────────────────────────────────────────────────┘
   ✓ success   ● текущий шаг (primary, вес 600, правая кнопка primary)   ○ muted
```

Правила состояний:

| № | Шаг | ✓ когда | Текст-сводка | Ссылка / действие |
|---|---|---|---|---|
| 1 | Программа | `disciplines.length > 0 && sessions.length > 0` | «N видов · M сессий» / «Добавьте сессии и виды» | `/program` |
| 2 | Регистрация открыта | статус ∈ {REGISTRATION_OPEN, REGISTRATION_CLOSED, LIVE, COMPLETED} | «до ДД.ММ ЧЧ:ММ · лимит X/Y» / «Опубликуйте и откройте регистрацию» | кнопка перехода статуса (та же, что в карточке «Регистрация») |
| 3 | Заявки | `registrations.length > 0` и нет SUBMITTED/UNDER_REVIEW | «N · M на рассмотрении» | `/entries?status=SUBMITTED` |
| 4 | Заплывы сформированы | у каждого вида с заявками есть heats | «K из N видов» | `/heats` → primary «Сформировать» |
| 5 | Стартовый протокол | все heats `isHeatPublished` | «опубликован ДД.ММ» / «не опубликован» | `/heats` |
| 6 | Результаты | heats FINISHED == heats.length | «K из N заплывов» | `/results` |
| 7 | Завершено | статус COMPLETED/ARCHIVED | — | кнопка «Завершить соревнование» (на шаге 6 выполненном) |

Иерархия — ровно четыре варианта, один primary на экран/карточку:

## 8. Чего не делать в v2

- Не менять палитру D01, шрифты, тёмную тему D02, правила печати, протокол и табло (они уже прошли axe/Lighthouse 100).
- Не переписывать страницы с нуля и не переносить все CSS-модули на новые классы — только точечная замена кнопок/бейджей/шапок там, где это указано в задании.
- Не вводить UI-библиотеки, иконочные шрифты, CSS-in-JS, Tailwind; иконки — inline SVG.
- Не добавлять новых серверных контрактов, кроме проверки документов и полей в `GET /registrations/me` (только добавление).
- Не делать настоящий пошаговый мастер, массовые действия с бэкендом, лист награждения, Lenex, режим ТВ-табло — этап 2 (WAVE5).
- Не менять ключи `localStorage` (`flounder.theme`, `flounder.auth-session`) — новые ключи с префиксом `sportgate.`.
- Не менять роли, маршруты безопасности и TSV, кроме новой строки для проверки документов.
