# D03 — UX-аудит интерфейса SportGate (Flounder) до демо 19.10.2026

Дата: 15.10.2026 (ночь). Автор: продакт-менеджер + UX-аналитик (агент волны 5). Метод: аудит по коду `sport-platform/frontend/src` (маршруты `app/App.tsx`, все страницы `features/*`, слои `AppLayout`/`OrganizerLayout`/`OrganizerEventLayout`/`PublicLayout`), по снимкам `docs/design/screenshots/*.png` и `docs/qa/screenshots/*.png`, по публичному API стенда `https://sportgate.pro/api/v1/public/events/...` (без входа; браузер в этом прогоне не использовался). Учтены прошлый аудит `docs/qa/QA06-ui-ux.md` (открытые QA06-06…14, 17–19, 21 здесь не повторяются, только ссылки), `docs/07_CJM_выверка.md`, `docs/demo-script.md`, `docs/design/D01_Концепция.md`, `D02_Проверка.md`.

Главный вывод: **визуально интерфейс после D01/D02 уже аккуратен, проблема не в «красоте», а в архитектуре навигации и в отсутствии «ведущей руки»**. Организатор после входа попадает не в свой кабинет, а в публичный каталог; видит три уровня меню с дублирующимися словами («Обзор» два раза, «Заявки» два раза, «Мероприятия/События/Мои события/Соревнование» вперемешку); карточка события не говорит, что делать дальше; у секретаря нет ссылки на событие вообще; судье нужно 4 действия, чтобы открыть заплыв. Всё это решается в основном текстами, перестановкой ссылок и одной новой компонентой «следующий шаг» — большая часть правок уровня S/M и укладывается до 16.10.

### 2.2 Секретарь (роль `operator`)

- Шапка: «События · Результаты · Заявки и платежи · Сменить пароль · Выйти». **Нет «Мои события»** (`canManageEvents = isPlatformAdmin || isOrganizer`), хотя маршруты `/organizer/**` для `operator` открыты — в кабинет события секретарь попадает только по прямой ссылке. Демо-сценарий (шаг 3) требует от секретаря «отметить оплату через свой кабинет» — без ссылки в меню ведущий будет вводить URL.
- «Заявки и платежи» (`OperatorPaymentsPage`) — отдельный старый экран со списком платежей по ID (QA06-19), не связан с вкладкой «Заявки» события.
- «Результаты» → `CompetitionUnitsPage` (см. 2.3).

Положительное: маска времени, Enter/Tab по дорожкам, DNS/DNF/DSQ кнопками и Alt-клавишами, статус «Сохранено 12:04», бейдж «исправлено» — ядро ввода сделано правильно и соответствует «ввод 8 дорожек ≤ 60 с».

## 4. Целевая информационная архитектура

### 4.1 Шапка (одна для всех ролей)

`SportGate` (логотип → ролевая главная) · **Соревнования** (`/` публичный каталог) · [по роли: **Мои соревнования** `/organizer/events` | **Мои заявки** `/my/registrations` | **Судейство** `/operator/results`] · [админ: **Администрирование ▾**] · **{Имя} · {роль} ▾** (Сменить пароль · Выйти).

Убрать из шапки: «Заявки» (UUID-форма), «Заявки и платежи» (перенести в кабинет события как фильтр «Оплата»), отдельный «Сменить пароль».

### 4.2 Кабинет организатора / секретаря

Боковое меню (`/organizer/**`), для operator — только первые два пункта:

1. **Соревнования** — список с фильтром по статусу (Черновик / Регистрация / Идёт / Завершено / Архив), сортировка по дате, карточка строки: название · дата по площадке · статус · «заявок N» · «Открыть».
2. **Создать соревнование** — мастер (§4.3).
3. **Регламенты** — список версий + «Создать».
4. **Настройки** — уведомления, площадки организации (этап 2), сотрудники (этап 2).
5. **Аналитика** (organizer/admin).

Дашборд `/organizer` не нужен как отдельный экран: редирект на «Соревнования»; если у организатора одно активное соревнование — сразу в него.

### 4.3 Карточка соревнования = «центр управления» (`/organizer/events/:id`)

### 4.4 Мастер «Создать соревнование» (3 шага, ≤ 10 минут)

1. **Основное** — название, даты соревнования (от/до, время площадки), площадка (селект + «Добавить площадку» inline: название, город, дорожки, длина, часовой пояс), описание, положение (файл PDF или ссылка; необязательно). Организация подставляется автоматически, если одна.
2. **Регистрация** — открытие/закрытие регистрации (по умолчанию: открытие сейчас, закрытие за 1 день до старта 09:00), лимит участников (необязательно), взнос (отметка «оплата вручную»), какие документы требуются (чекбоксы).
3. **Программа** — сессии (дата/время, пауза) и виды: выбор из шаблонов «50 в/с · 100 в/с · 50 на спине …» чекбоксами × пол, пресет групп («детские 2 года»), порядок автоматически; всё правится потом на вкладке «Программа».

Финал: «Соревнование создано как черновик» → кнопки «Опубликовать и открыть регистрацию» / «Перейти в карточку».

### 4.5 Судейство (`/operator/results`)

Список «Сегодня» (события в статусе LIVE/регистрация закрыта на дату) → сессии → заплывы с бейджами; большая кнопка «Текущий заплыв». Панель ввода (UX-11): контекст в шапке, одна первичная кнопка по состоянию, таблица дорожек, свёрнутая подсказка.

### 4.6 Участник / родитель
