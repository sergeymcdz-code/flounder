# D04-0 — Спецификация редизайна экранов SportGate (Flounder)

Дата: 2026-10-24. Основание: токены и компоненты D04-1 (PR #104, `sport-platform/frontend/src/styles/tokens.css`, `components.css`, `components/ui/*`, `docs/design/D04_Дизайн-система.md`), аудит QA08 (`docs/qa/QA08-ui-defects-2026-10-24.md`, 22 дефекта), решения D01–D03. Макеты-ориентиры: `D04_Макеты.html` и снимки `D04-mock-*.png` рядом с этим файлом.

Цель документа: 12 агентов Codex переверстают экраны параллельно и получат **один** продукт, а не 12 стилей. Поэтому здесь жёстко зафиксированы: сетка, навигация, типографика цифр, паттерн «таблица → карточка», набор компонентов на экран, распределение файлов без пересечений и единые критерии приёмки.

Правила, которые действуют на всех задачах:

1. Цвета, размеры, радиусы, тени — **только** из `tokens.css`. Новых CSS-переменных не вводить. Хардкод hex/px для цвета и отступов запрещён (исключение: `1px` границы и литералы брейкпоинтов в `@media`, т.к. CSS-переменные там не работают).
2. Статусы — только `StatusBadge` + `status-dictionary.ts`. Кнопки — только `Button` (или классы `fl-btn fl-btn-*` там, где нужен `summary`/`a`). Таблицы с данными — `DataTable` или `table.fl-table` внутри `.fl-table-scroll`/`.fl-data-table-scroll`. Пустые состояния — `EmptyState`, предупреждения — `Notice`, подтверждения — `ConfirmDialog`, уведомления — `useToast`.
3. Тексты интерфейса — русские, в терминах D03 («соревнование», «заявка», «заплыв», «вид программы», «стартовый протокол», «табло», «результаты»).
4. Три ширины обязательны: 375, 768, 1366. Горизонтальный скролл страницы (`document.documentElement.scrollWidth > clientWidth`) на любой из них — блокер PR.
5. Каждый экран имеет четыре состояния: загрузка, пусто, ошибка (с текстом и следующим шагом), данные. Состояние «ошибка» не затирает уже показанные данные без необходимости.

## (а) Общие правила раскладки

### А1. Сетка и отступы

| | 375 (mobile, <768) | 768 (tablet, 768–1023) | 1366 (desktop, ≥1024) |
|---|---|---|---|
| Боковые поля страницы | `--space-4` = 16 px | `--space-6` = 24 px | `--space-8` = 32 px |
| Ширина контента, кабинет | 100 % − 32 | 100 % − 48 | `min(100% − 64px, var(--content-max) = 1280px)` |
| Ширина контента, публичные | 100 % − 32 | `min(100% − 48px, 960px)` | 960 px (`--content-max` не применяется; табло и протоколы — 960, как в D01) |
| Вертикальный ритм между блоками | `--space-4` | `--space-6` | `--space-6` |
| Карточка `.fl-card` padding | `--space-4` | `--space-6` | `--space-6` |
| Колонки форм | 1 | 1 (парные поля — 2 только для «Фамилия/Имя», «Дата/Пол») | 2 для парных, остальное 1; максимум ширины формы 640 px |
| Карточки списков (календарь, события) | 1 колонка | 2 колонки | 3 колонки (`grid-template-columns: repeat(auto-fill, minmax(300px, 1fr))`) |

Базовый шаг 4 px: допустимые отступы только `--space-1…12/16`. Радиусы: контролы `--radius-sm`, поля `--radius-md`, карточки и диалоги `--radius-lg`. Тени: карточки плоские (`--shadow-card: none`), тень только у поповеров/тостов (`--shadow-pop`) и закреплённых панелей (`--shadow-sticky`, `--shadow-drawer`).

Толстая линейка `--border-width-rule` (3 px, цвет `--border-rule`) — фирменный элемент «стартового протокола»: только под `PageHeader`, под активной вкладкой, у `.fl-heat`, `.fl-rule`. Не использовать как границу карточек.

### А2. Шапка и навигация

**Одна шапка на весь продукт** (закрывает UI-015). Высота `--header-h` = 56 px, фон `--surface-1`, низ — `--border-width-rule`. Состав слева направо:

```
[ S ] SportGate   | контекст (на страницах события: название · дата · город, 14 px, muted) |   … [Войти / Имя ▾]  [Тема]
```

- Логотип: квадрат 32 px с «S» (как в `PublicLayout` сейчас) + слово SportGate Oswald 600 20 px. На 375 слово остаётся, контекст события уходит под шапку отдельной строкой (`.eventMeta`) — как сейчас в `/e/:slug`.
- Правая часть: аноним — ghost «Войти»; авторизованный — `details` «Имя · роль» с меню (Мои заявки / Мои соревнования / Судейство / Администрирование… / Сменить пароль / Выйти). Меню — поповер `min-width: 240px`, пункты 44 px, не обрезаются (закрывает UI-006). `ThemeToggle` показывать на публичных страницах всегда; в кабинете — в меню пользователя.
- Ссылки верхнего уровня («Соревнования», «Мои соревнования») — на ≥768 в шапке, на 375 — в бургере.

**375, кабинет (organizer/operator/judge/admin):** бургер 44×44 справа открывает **выдвижную панель** (`position: fixed; inset: 0 0 0 auto; width: min(320px, 100% − 56px); box-shadow: var(--shadow-drawer); z-index: var(--z-drawer)`), в ней три группы: 1) верхние разделы; 2) пункты бокового меню кабинета (Соревнования, Регламенты, Публичная страница организации, Настройки, Аналитика, Организация; для admin — пять админских ссылок); 3) блок пользователя (имя, роль, Сменить пароль, Выйти). Горизонтальная «лента чипов» бокового меню на телефоне **убирается** (закрывает UI-016). Нижней навигации в кабинете нет (конфликт с панелью действий судьи и с клавиатурой при вводе).

**375, публичные страницы события `/e/:slug/*`:** нижняя закреплённая панель 56 px «Протокол · Расписание · Табло · Результаты (· Зачёт)» сохраняется (D01) — это мобильный способ переключаться между разделами одного соревнования. На **≥1024** панель становится `position: sticky; top: var(--header-h)` строкой-вкладками (`Tabs`) под шапкой и не перекрывает таблицы (закрывает UI-017). Строка «Календарь · Страница организации» под шапкой превращается в хлебную крошку слева от вкладок: «← Календарь».

**768/1366, кабинет:** боковое меню 232 px (`--sidebar-w`), sticky под шапкой, как в D03; на 768–1023 — тоже 232 px, контент `minmax(0, 1fr)` (таблицы прокручиваются внутри). Ниже 768 меню не показывается (ушло в drawer).

**Вкладки события** (`Tabs`): на всех ширинах — горизонтальная прокрутка с градиент-тенью **с обеих сторон** (не только ≤767; закрывает UI-003), активная вкладка `scrollIntoView`. Счётчики — короткие: `Заявки 128 ·3` (число + attention-бейдж), `Заплывы 6` + отдельный маленький бейдж статуса «черновик/опубликовано» **только** на вкладке «Заплывы»; длинные подписи («6 · черновик», «0 из 6», «4 вида») убираются. Вкладки «Грамоты», «Командный зачёт», «Уведомления», «Аналитика» переезжают в меню «⋯» рядом с вкладками на ширинах < 1366 и остаются вкладками на ≥1366. Итого видимых вкладок ≤ 7: Главная · Программа · Заявки · Оплата · Заплывы · Результаты · ⋯.

**Ссылка «назад»** — один паттерн: `Button variant="ghost" size="sm" as={Link}` с «←», блок (`display: inline-flex`, min-height 44 на mobile), всегда над `PageHeader`, никогда «голая» `<Link>` перед `h1` (закрывает UI-007, UI-019).

### А3. Типографика

| Роль | Шрифт | Размер 375 / 1366 | Где |
|---|---|---|---|
| Display | Oswald 600, `--line-height-tight` | `--text-xl` 28 / `--text-2xl` 40 | Название соревнования на `/e/:slug`, «Соревнования по плаванию» на `/` |
| Номер заплыва на табло | Oswald 700 | `--text-2xl` 40 / `--text-display` 64 | Live-табло, панель судьи («ЗАПЛЫВ 3 из 12» — 28) |
| H1 страницы | Oswald 600 | `--font-size-24` / `--text-xl` 28 | `PageHeader` |
| H2 блока | Oswald 600 | `--font-size-20` / `--font-size-20` | Карточки |
| Текст | Golos 400 | `--text-md` 16 | |
| Мета, подписи | Golos 400 | `--text-sm` 14 / `--text-xs` 12 | muted |
| Eyebrow (надзаголовок) | Golos 600, caps, letter-spacing .05em | 12 | **цвет `--color-text`** или `--color-primary`, не muted (контраст; закрывает UI-020) |

**Цифры.** Всё, что сравнивается глазами по вертикали — время, места, дорожки, суммы, годы, счётчики — `font-variant-numeric: var(--numeric-variant)` (класс `.fl-numeric` или `data-numeric` в таблицах), выравнивание вправо, `white-space: nowrap`. Результат заплыва/заявочное время в таблицах — Golos 600 16 px tnum; на табло и в панели судьи — Oswald 24–28 px tnum (`.fl-stopwatch`). Формат времени везде `мм:сс.сс` (`00:32.15`), а не «32,15».

### А4. Карточки vs таблицы

| Данные | ≥768 | 375 |
|---|---|---|
| Списки сущностей с действиями (заявки, пользователи, оплата по клубам, события кабинета) | `DataTable`, `minWidth` по числу колонок, `maxHeight` ≤ `min(60vh, 640px)` → **прокрутка внутри контейнера**, никогда страницы | **Карточки строк** (паттерн А5) |
| Протоколы (дорожки, результаты вида) | таблица `.fl-protocol` без ограничения высоты (печать) | та же таблица, колонки по приоритету А5; первые две sticky |
| Сводки (цифры) | сетка `.fl-summary-cell` 3–5 в ряд | 2 в ряд |
| Списки навигации (разделы события, «Далее» на табло) | карточки-ссылки | карточки-ссылки в 1 колонку |

Любой контейнер с `overflow-x: auto` обязан показывать **признак прокрутки**: градиент-тень справа (и слева при `scrollLeft > 0`) + `scrollbar-width: thin`. Реализация — утилита `.fl-scroll-x` (см. раздел д, предложение 2); до её принятия — те же три правила копируются в CSS-модуль экрана дословно.

### А5. Паттерн «таблица → карточка» и приоритет полей

У каждой колонки задаётся приоритет: **P1** — всегда; **P2** — скрыта на <768 (`data-priority="low"` уже скрывает на ≤1366, этот порог для задач ниже заменяется на 767 внутри `.fl-rowcards`-контейнера); **P3** — только ≥1366 или в раскрывашке.

На 375 строка таблицы становится карточкой (`.fl-rowcards` — предложение 3; до принятия — локальный CSS по этому же описанию):

```
┌──────────────────────────────────────────────┐
│ P1-идентификатор (ФИО / клуб / email)  [Бейдж]│  ← 16 px 600, бейдж справа
│ P1-мета: вид · год · клуб                     │  ← 14 px muted
│ P1-число (время / сумма)          00:32.15    │  ← tnum, вправо, Golos 600
│ [Основное действие]              [ ⋯ ]        │  ← 44 px, primary/secondary + меню
└──────────────────────────────────────────────┘
```

Правила: чекбокс выбора — слева в первой строке; не более **одной** видимой кнопки + «⋯»; P2/P3 поля — внутри `details` «Подробнее» в карточке; высота карточки не ограничена; между карточками `--space-2`; фон `--surface-1`, граница `--border-subtle`, радиус `--radius-md`.

Приоритеты по экранам — в разделе (б).

### А6. Состояния

- **Загрузка:** `LoadingState`/`<p role="status">` c текстом «Загружаем …». Для таблиц — три серые строки-плейсхолдера (фон `--surface-2`, высота 44, радиус `--radius-sm`) вместо пустого контейнера. Кнопки в `loading` сохраняют размер.
- **Пусто:** `EmptyState` с заголовком, одной фразой и одним действием (ссылка на следующий шаг).
- **Ошибка:** `Notice tone="danger"` рядом с местом, где должны быть данные, + кнопка «Повторить». Текст различает «Нет связи…» (TypeError/offline) и «Сервер ответил ошибкой (код)» / «Данные не найдены» (QA08 §7).
- **Disabled с причиной:** любая `disabled`-кнопка получает `title` и видимый `small` с причиной под/рядом («Нет текущего заплыва», «Сначала сформируйте заплывы») — закрывает UI-014, UI-018.
- **Нет прав:** `Notice tone="neutral"` вместо группы кнопок; кнопки не рендерятся.

### А7. Тёмная тема

Принудительно тёмные (через существующие `:has(.fl-live-page)`, `:has(.fl-results-page)`): `/e/:slug/live`, `/e/:slug/results`. Остальные публичные страницы — по `ThemeToggle`. Кабинет — по `ThemeToggle` (в меню пользователя). Любой новый CSS обязан использовать семантические токены (`--surface-*`, `--color-text*`, `--border-*`) — тогда тёмная тема «приходит сама». Проверка: снимок каждого экрана в обеих темах.

### Б2. Карточка события `/e/:slug` (D04-2c)

**Цель:** за 5 секунд понять, что/где/когда и что делать: подать заявку / смотреть табло / результаты. **Главное действие:** «Подать заявку» (при открытой регистрации) или «Табло» (LIVE) или «Результаты» (COMPLETED) — ровно одна primary по статусу.

**375:**
1. Шапка + строка контекста события (общая).
2. Hero-блок без карточки: eyebrow «Соревнования по плаванию», H1 Oswald 28, под ним `StatusBadge` события, строка фактов 14 px: `15.10.2026 · Бассейн «Дельфин», Самара · 8 дорожек · 25 м`.
3. **Primary-действие на всю ширину (size lg, 56 px)** по статусу: REGISTRATION_OPEN → «Подать заявку» (+ под ним muted «Взнос от 500 ₽ · до 13.10 19:00»); LIVE → «Открыть табло» с бейджем ● Идёт; COMPLETED → «Результаты»; иначе — «Стартовый протокол».
