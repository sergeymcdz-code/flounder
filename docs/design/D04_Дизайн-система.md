# D04 — дизайн-система SportGate, этап 1

Фундамент редизайна Flounder: токены, общие UI-компоненты и витрина. Структура рабочих экранов, API и маршруты существующих сценариев не меняются. Новые компоненты внедряются в экраны в D04-2 и следующих задачах.

## Визуальный язык

Спортивный протокол: чёткая иерархия, ровные колонки чисел, спокойные поверхности и контрастные статусы. Синий «вода» обозначает основное действие, тёплый «финиш» — смысловой акцент. Цвет не заменяет текст статуса. Основной шрифт — локальный Golos Text, заголовки и табло — Oswald; внешних запросов к шрифтам нет.

| Группа | Токены / значения | Правило |
| --- | --- | --- |
| Размер текста | `--font-size-12/14/16/18/20/24/28/32` | 12–14: метаданные, 16: текст, 20–32: иерархия заголовков |

| Начертания | `--font-weight-medium` = 600, `--font-weight-bold` = 700 | Не применять жирность ко всему тексту |
| Интерлиньяж | `--line-height-tight` = 1.2, `--line-height-body` = 1.5 | Плотные заголовки, читаемые абзацы |
| Цифры | `--numeric-variant: tabular-nums lining-nums` | Время, места, суммы, дорожки; класс `.fl-numeric` |
| Отступы | `--space-0` = 0; `--space-1…12` = 4…48; `--space-16` = 64 px | Основная сетка 4 px; прежние внутренние 6/10 px у компактных контролов сохранены |
| Радиусы | `--radius-none/sm/md/lg/pill` = 0/3/5/8/999 px | Малые для контролов, lg для контейнеров |
| Тени | `--shadow-none`, `--shadow-card`, `--shadow-pop`, `--shadow-sticky`, `--shadow-drawer` | Карточки плоские; тени только у всплывающих и закреплённых элементов |
| Слои | `--z-sticky/header/drawer/dialog/toast` = 10/20/30/40/50 | Нативный modal dialog использует top layer |
| Контролы | `--control-h-sm/h/lg` = 36/44/56 px; `--tap-target` = 44 px | На мобильных sm также не меньше 44×44 |
| Брейкпоинты | `--breakpoint-mobile/tablet/desktop/wide` = 375/768/1024/1366 px | 375 — минимальная ширина ревью; мобильные <768, планшеты <1024 |
| Движение | `--motion-fast/base` = 120/200 ms; `--ease` | Учитывать `prefers-reduced-motion` |

CSS-переменные нельзя использовать в условиях `@media`: значения 767/1023/1366 записываются литералами. Имеющиеся адаптивные правила 480 px сохранены, чтобы не перестраивать прежние протоколы. В коротком desktop viewport (от 1024 px, высота до 800 px) вертикальный padding ячеек текущего заплыва приведён с 5 к 4 px: восемь дорожек и действие помещаются над нижней навигацией. Это устраняет воспроизводимый на исходном main сбой QA06 без изменения структуры страницы или мобильного протокола.

## Статусы

Все статусы в новых и перерабатываемых экранах выводятся через `StatusBadge`. Словарь `status-dictionary.ts` — единый источник русских подписей и тонов; неизвестный код остаётся видимым с нейтральным оформлением. Не вводить локальные цветные бейджи или вторые словари. В старых экранах сохранены совместимые CSS-классы до их отдельного редизайна.

| Группа | Семантические токены и соответствия |
| --- | --- |
| Общие тона | `--status-neutral/info/success/warning/danger` и соответствующие `*-soft` |
| Заявки | `--status-registration-{code}` и `*-soft`: submitted/under-review → info; confirmed/paid/admitted → success; waitlisted/needs-correction → warning; rejected/cancelled → danger; withdrawn → neutral |
| Результаты | `--status-result-{code}` и `*-soft`: valid/pending/dns/dnf → neutral; dsq → danger; corrected → warning |
| Совместимость событий и заплывов | `--status-draft/published/live/finished/withdrawn/dns/dnf/dsq` и `*-soft` |

`StatusBadge` добавляет `data-status-kind` и нормализованный `data-status`; стили заявок и результатов используют их семантические токены. LIVE имеет пульсирующую точку с отключением анимации при reduced motion. Текст остаётся обязательным. VALID сохраняет прежнюю подпись «—» в колонке статуса: сам результат находится в колонке времени.

## Компоненты

Импорты ниже — из `src/components/ui/*`; API прежних компонентов совместим с существующими экранами.

```tsx
<Button variant="primary" size="md" loading={saving} onClick={save}>Сохранить</Button>
<Button variant="secondary" size="sm">Отмена</Button>
<Button variant="ghost" as={Link} to="/organizer/events">К списку</Button>
<Button variant="danger" size="lg" onClick={openConfirm}>Снять заявку</Button>
<StatusBadge kind="registration" code="NEEDS_CORRECTION" />
<StatusBadge kind="result" code="DSQ" />
```

Button: primary — основное действие; secondary — второе; ghost — навигация/малозначимое действие; danger — разрушительное действие через подтверждение. sm/md/lg: 36/44/56 px на desktop, не меньше 44 px на mobile. Loading сохраняет геометрию и доступное имя, ставит `aria-busy`, блокирует повторное нажатие и переходы ссылок. У ссылки можно задать `aria-disabled`; у кнопки — `disabled`. Кнопка по умолчанию `type="button"`, в форме явно задавать submit. Контент не должен содержать вложенные интерактивные элементы.

```tsx
<PageHeader title="Кубок SportGate" meta="24.10.2026 · Самара"
  badge={<StatusBadge kind="event" code="PUBLISHED" />}
  actions={<Button variant="primary">Опубликовать</Button>} />
<Tabs label="Разделы соревнования" items={[
  { to: '/organizer/events/123', label: 'Обзор' },
  { to: '/organizer/events/123/entries', label: 'Заявки', count: 128, attention: 3 },
]} />
<ActionBar><Button variant="primary">Сохранить</Button><Button>Отмена</Button></ActionBar>
<EmptyState title="Заплывов пока нет" action={<Button>Добавить заплыв</Button>}>
  <p>Добавьте первый заплыв для подготовки протокола.</p>
</EmptyState>
<Notice tone="warning">Три заявки требуют исправления.</Notice>
```

PageHeader складывает действия под заголовок на mobile. Tabs — навигационные ссылки с `aria-current`, именованными счётчиками и внутренней прокруткой. Не использовать `role="tab"` для переходов между маршрутами. ActionBar переносит действия, на mobile располагает их вертикально. EmptyState объясняет отсутствие данных и даёт действие. Notice поддерживает neutral/info/warning/danger; danger объявляется как alert.

```tsx
// Внутри существующего ToastProvider, один раз на приложение:
const toast = useToast()
toast({ text: 'Изменения сохранены', tone: 'success' })
toast({ text: 'Не удалось сохранить. Повторите попытку.', tone: 'danger' })

{confirmOpen && <ConfirmDialog title="Снять заявку?"
  description="Участник увидит причину снятия." confirmLabel="Снять заявку"
  tone="danger" reason busy={saving} error={error}
  onConfirm={reason => withdraw(reason)} onClose={() => setConfirmOpen(false)} />}
```

Toast объявляет сообщение через polite live region и закрывается через 5 секунд; важная ошибка также должна оставаться рядом с формой через Notice. ConfirmDialog использует нативный modal dialog, удерживает фокус и возвращает его на триггер. Для danger начальный фокус на отмене. `reason` включает поле причины, по умолчанию обязательное; `reasonRequired={false}` делает его необязательным. `busy` блокирует повторное действие и Escape, `error` показывает ошибку без закрытия диалога. UI-компонент больше не зависит от стилей страницы организатора.

```tsx
<DataTable caption="Женщины · 50 м · Финал" rows={results}
  rowKey={row => row.id} minWidth={760} maxHeight={360} compact
  emptyMessage="Результатов пока нет" columns={[
    { key: 'place', header: 'Место', numeric: true, render: row => row.place },
    { key: 'name', header: 'Участница', rowHeader: true, render: row => row.name },
    { key: 'time', header: 'Время', numeric: true, render: row => row.time },
    { key: 'status', header: 'Статус', render: row => <StatusBadge kind="result" code={row.status} /> },
  ]} />
```

DataTable: нативная table с caption и scope, стабильные ключи строк, липкий заголовок, числовые колонки справа с табличными цифрами, обычная/компактная плотность, пустое состояние. Именованный region доступен с клавиатуры. Широкая таблица прокручивается внутри контейнера по обеим осям. Для фактически широких данных задавать minWidth. flex/grid-родитель также должен иметь `min-width: 0` или `minmax(0, 1fr)`. При печати ограничение высоты и sticky снимаются.

## Обязательные правила

1. Ни один экран не должен давать горизонтальный скролл страницы на 375 px. Не маскировать ошибку через `overflow-x: hidden` у body; ограничивать и прокручивать конкретный контейнер.
2. Все интерактивные элементы на mobile имеют область нажатия ≥44×44 px, включая sm-кнопки, иконки, ссылки-действия и подписи чекбоксов. Строки таблицы могут быть компактнее, если не содержат интерактивных элементов.
3. Все статусы — через StatusBadge; цвет дополняет подпись. Для времени и мест — tabular-nums. Числа выравниваются вправо, имена — влево.
4. Focus-visible обязателен. Действия должны работать мышью, касанием и клавиатурой. Loading и disabled не должны менять ширину кнопок или оставлять работающий обработчик перехода.
5. Опасные и публичные изменения подтверждаются диалогом. Ошибки имеют русский текст и следующий шаг. Не оставлять видимые кнопки без обработчиков.
6. Контраст обычного текста — не меньше 4.5:1, крупного текста и значимых границ/фокуса — 3:1. Проверять обе темы и печать. Проверенные пары primary/info/accent/success/warning/danger/muted: минимум 5.05:1 в светлой теме и 6.78:1 в тёмной.

## Витрина и проверка

```bash
cd sport-platform/frontend
npm ci
npm run dev              # /dev/ui без API
npm run dev:demo         # /dev/ui также доступна
npm run build && npm run lint && npm test
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium npm run test:qa06
```

`/dev/ui` и демонстрационные вкладки `/dev/ui/*` включены только при `import.meta.env.DEV` или mode=demo. Обычная production-сборка не включает маршрут, модуль или CSS витрины. Demo — специальный режим, не production-деплой. API существующих страниц не менялся.

Для ручного ревью: открыть /dev/ui, переключить тему, проверить варианты и размеры кнопок, loading/reset, обе плотности таблицы, горизонтальную прокрутку клавишами, Toast, обычный диалог и диалог с причиной, Escape и возврат фокуса. Повторить на ширинах 375 и 1366.

Автопроверка `qa06-d04-ui.spec.ts` создаёт четыре полноразмерных снимка в git-ignored `test-results/d04`; чтобы обновить снимки в репозитории, задайте `D04_SCREENSHOTS=../../docs/design/screenshots npm run test:qa06 -- e2e/qa06-d04-ui.spec.ts`. Дополнительно проверяются отсутствие скролла страницы, mobile target size, табличные цифры, переключение тем, диалог и Toast. Остальные QA06-тесты проверяют существующие экраны; opt-in audit capture остаётся отдельным режимом QA06_CAPTURE.
