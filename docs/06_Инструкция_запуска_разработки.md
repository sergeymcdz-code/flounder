### Лимит попыток входа (S04)

`APP_AUTH_LOGIN_MAX_FAILURES` (`app.auth.login.max-failures`, по умолчанию 5)
ограничивает число неверных паролей по нормализованному email.
`APP_AUTH_LOGIN_MAX_FAILURES_PER_IP` (`app.auth.login.max-failures-per-ip`, по умолчанию 30)
задаёт независимый порог по IP. Окно для обоих — `APP_AUTH_LOGIN_WINDOW`
(`app.auth.login.window`, по умолчанию `PT15M`). Успешный вход сбрасывает только email.
После достижения порога следующий запрос получает 429 и `Retry-After` в секундах.

Адрес берётся из `HttpServletRequest.getRemoteAddr()`. В prod включён
`server.forward-headers-strategy=native`: Tomcat RemoteIpValve обрабатывает
`X-Forwarded-For` только от внутренних доверенных прокси. Caddy формирует этот
заголовок из адреса TCP-клиента, игнорируя присланный клиентом заголовок;
порт API в compose не опубликован и доступен только во внутренней сети.
Контроллер сам заголовок не разбирает. При добавлении внешнего балансировщика
границу доверия нужно настроить отдельно.

**Действие владельца при деплое после демо 19 октября:** выставить
`APP_AUTH_LOGIN_MAX_FAILURES=5`, `APP_AUTH_LOGIN_MAX_FAILURES_PER_IP=30`
в `infra/.env.prod`, затем пересоздать API с обновлённым compose из репозитория:
он передаёт обе переменные в контейнер. Значения и compose на сервере
этим заданием не меняются.
Капча отложена до завершения пилотов.
