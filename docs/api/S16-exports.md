# S16: экспорт протоколов и зачёта

Экспорт доступен без изменений frontend. Авторизованные маршруты используют те же роли и проверку события, что PDF: `organizer`, `operator` (секретарь) своей организации либо `platform_admin`. Судья и участник получают 403, запрос без авторизации — 401, организатор чужой организации — 403. Архивные события доступны для чтения.

## Маршруты

| Метод | Путь | Содержимое |
| --- | --- | --- |
| GET | `/api/v1/organizer/events/{id}/exports/results.xlsx` | Результаты XLSX |
| GET | `/api/v1/organizer/events/{id}/exports/results.csv` | Результаты CSV |
| GET | `/api/v1/organizer/events/{id}/exports/standings.xlsx` | Командный зачёт XLSX |
| GET | `/api/v1/organizer/events/{id}/exports/standings.csv` | Командный зачёт CSV |
| GET | `/api/v1/organizer/events/{id}/exports/start-list.xlsx` | Стартовый протокол XLSX |
| GET | `/api/v1/organizer/events/{id}/exports/start-list.csv` | Стартовый протокол CSV |
| GET | `/api/v1/public/events/{slug}/exports/results.csv` | Опубликованные результаты CSV, без авторизации |

Публичный экспорт повторно проверяет видимость события при каждом запросе. Включает только дисциплины `PUBLISHED`, заплывы `FINISHED`/`COMPLETED` и результаты, отличные от `PENDING`. Если опубликованных строк нет, возвращается 404 `results.public_not_found`. Невидимое или неизвестное событие — 404 `events.public_not_found`. Контактные данные, адреса и UUID спортсменов в файлы не попадают. Внутренний экспорт результатов включает черновики и строки без результата (`NT`).

## Форматы и колонки

Оба формата начинаются с двух строк метаданных: название события и документа; затем `Предварительно` / `Официальный протокол`, ключ `official` и boolean. Третья строка — названия колонок, далее данные. В XLSX есть печатный нижний колонтитул с той же отметкой и повторяемая строка заголовков. Данные идут в порядке сессий и видов программы; результаты внутри вида — по месту, времени и имени; стартовый протокол — по номеру заплыва и дорожке.

Списки колонок из генерируемых тестом XLSX/CSV:

- **results**: Вид программы; Место; Участник; Год; Клуб; Время/результат; Статус; Очки; official.
- **standings**: Место; Клуб; Очки; Золото; Серебро; Бронза; Зачтено результатов; official.
- **start-list**: Сессия; Вид программы; Заплыв; Плановое время; Группа; Дорожка; Участник; Год; Клуб; Заявочное время; Статус; official.

Время результата и заявки — `мм:сс.сс`; плановое время — ISO 8601 со смещением. Сессия без назначения — `Без сессии`, отсутствующее заявочное время — `NT`, снятая стартовая запись — `Снят`. Статусы результата: `VALID`, `NT`, `DNS`, `DNF`, `DSQ`. Для DNS/DNF/DSQ место пустое, очки равны 0; исправленный DNS/DNF/DSQ сохраняет исходный статус. Очки берутся из расчёта зачёта с действующими `scope`, `pointsByPlace`, `disciplineIds` и лимитом клуба. Незачтённые, снятые и неопубликованные результаты получают 0. У организатора зачёт выгружается и при выключенной публичной публикации зачёта; отдельно публиковать зачёт для экспорта результатов не требуется.

CSV: UTF-8 BOM (`EF BB BF`), разделитель `;`, окончания строк CRLF; значения заключены в двойные кавычки, внутренние кавычки удваиваются. Перед ведущими `=`, `+`, `-`, `@` добавляется апостроф, в том числе если перед ними есть пробельные символы. Защита применяется ко всем строковым значениям, включая метаданные. XLSX создаётся Apache POI, числа и boolean сохраняют тип; текст записывается строковыми ячейками, а не формулами.

Ответы содержат `Content-Disposition: attachment`, корректный `Content-Type` и `Cache-Control: no-store`. Для экспортов отключается буферизация общего фильтра ETag, чтобы публичный CSV тоже передавался потоком. Файл пишется непосредственно в `OutputStream` ответа; весь закодированный файл не собирается в `byte[]`. XLSX использует `SXSSFWorkbook` с окном 100 строк, сжатием временных файлов и удалением файлов при закрытии, в том числе при ошибке записи. Перед формированием ответа в транзакции `REPEATABLE_READ` создаётся ограниченный снимок данных. Лимит — 100 000 записей участников в выбранных заплывах; превышение возвращает 400 `documents.export_too_large` до записи заголовков/файла. Поддержка 10 000 строк проверяется через реальные endpoints обоих форматов.

## Официальный протокол

Единственный изменённый endpoint публикации:

```http
POST /api/v1/competition-units/{unitId}/publication
Content-Type: application/json

{"published":true,"official":true}
```

`official` — необязательный boolean. Старый запрос `{"published":true}` сохраняет поведение публикации и создаёт предварительный протокол. Явный `official` разрешён только `organizer`, `operator`, `platform_admin`; судья по-прежнему может публиковать без этого параметра. Для уже опубликованного заплыва `{"published":true,"official":true|false}` меняет утверждение после повторной проверки полноты результатов, без смены `FINISHED`/`COMPLETED` и повторной рассылки события публикации. `published:false, official:true` отклоняется с 400 `results.official_requires_publication`.

Миграция **V041__official_results.sql** добавляет `competition_units.official boolean NOT NULL DEFAULT false` и ограничение: официальный заплыв должен находиться в `FINISHED`/`COMPLETED`. Публикация в существующем API принадлежит заплыву, поэтому на уровне вида `official=true` только при наличии заплывов и официальности всех заплывов этого вида, включая ещё не опубликованные. На уровне события/целого файла — только если официальны все виды соответствующей программы; пустая программа или вид без заплывов остаются предварительными. Для публичного события учитываются только опубликованные виды; скрытые дисциплины не раскрываются. В каждой строке результатов/старта отражается флаг её вида; в строке зачёта — всего документа.

Снятие публикации сбрасывает флаг заплыва. Изменение результата через пакетный ввод сбрасывает утверждение всех заплывов вида, поскольку могут измениться места других спортсменов; повтор запроса без изменения результата сохраняет флаг. Одиночный ввод и ручной пересчёт сбрасывают флаг соответствующего заплыва.

Публичные DTO дополнены:

- `/public/events/{slug}/results`: `official` события и `disciplines[].official`;
- `/public/events/{eventId}/disciplines/{eventDisciplineId}/results`: `official` вида и `units[].official`;
- `/public/competition-units/{unitId}/results`: `official` заплыва.

JSON по slug сохраняет существующее кеширование до 10 секунд. Экспорты не кешируются.

Для новой БД V041 применяется в обычном порядке. В `main` уже существуют V050/V051: если они применены в целевой БД, V041 требует согласованного применения Flyway с `outOfOrder` при обновлении. Номер V041 закреплён заданием; старые миграции и глобальные настройки Flyway не меняются.

## Ручная проверка

Нужны существующее событие с заявками, посевом и рассчитанными результатами, его UUID/slug, UUID заплыва и JWT организатора. В примерах переменные заполняются значениями тестового события; токены не сохраняются в репозитории.

```bash
BASE=http://localhost:8080
EVENT_ID='<uuid события>'
SLUG='<slug события>'
UNIT_ID='<uuid заплыва>'
TOKEN='<JWT организатора>'

# 1. Предварительные результаты, старт и зачёт, оба формата.
for kind in results standings start-list; do
  for ext in csv xlsx; do
    curl --fail-with-body -H "Authorization: Bearer $TOKEN" \
      "$BASE/api/v1/organizer/events/$EVENT_ID/exports/$kind.$ext" \
      --output "$kind.$ext"
  done
done

# 2. Официальная публикация конкретного заплыва (повторить для остальных).
curl --fail-with-body -X POST -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  --data '{"published":true,"official":true}' \
  "$BASE/api/v1/competition-units/$UNIT_ID/publication"

# 3. Публичные DTO и CSV, без JWT.
curl --fail-with-body "$BASE/api/v1/public/competition-units/$UNIT_ID/results"
curl --fail-with-body "$BASE/api/v1/public/events/$SLUG/exports/results.csv" \
  --output public-results.csv

# 4. Снять публикацию; при отсутствии других опубликованных строк CSV вернёт 404.
curl --fail-with-body -X POST -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' --data '{"published":false}' \
  "$BASE/api/v1/competition-units/$UNIT_ID/publication"
curl -i "$BASE/api/v1/public/events/$SLUG/exports/results.csv"
```

Проверить BOM CSV, колонки и отметку протокола в Excel/LibreOffice. Запросить организаторский экспорт с JWT судьи/чужого организатора — ожидается 403, без JWT — 401. Каждый заплыв вида должен быть утверждён, прежде чем вид станет официальным.
