## Дефекты демо-сценария

Для показа 15.10 использовать обходы из последней колонки: организатор отмечает оплату, печать выполняется после публикации, результаты завершаются кнопкой «Финиш» вместо «Опубликовать». Последний обход требует оставить начатый заплыв в IN_PROGRESS: после публикации исходный сценарий уже попадает в QA05-09 и потребует дополнительного «Старт». Управление circleSeedTopHeats и WARNING о снятии не обещать в реплике. Обходы требуют репетиции и не закрывают дефекты; автотест сохраняет исходные падающие проверки.

## Не удалось проверить и почему

- Полный UI-путь оплаты секретаря — QA05-02. Сохранён снимок ошибки и 403 в сетевом аудите; отдельные действия секретаря с реальными правами operator проходили через API и судейскую панель.

- Публичную выдачу результатов/исправления до завершения заплывов и штатный «Финиш» после публикации — QA05-07/09. Обходы отмечены, падающие проверки сохранены.
- Обязательный WARNING опубликованного снятия — QA05-08.
- Production sportgate.pro, установка на физическом Android/iOS, QR через мобильную сеть, печатный принтер и видео/реальная 14-минутная репетиция не проверялись. PWA проверена в Chromium на безопасном localhost; это не подтверждает установку на физических устройствах.
- На mocks не засчитан ни один шаг. Не выполнялись redesign, изменение backend RBAC/жизненного цикла или миграции. Контракты серверных API не менялись.
