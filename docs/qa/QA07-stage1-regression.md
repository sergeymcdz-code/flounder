## Правки по ревью 1

- П.1в теперь покрыт M02 e2e на отдельных пользователях, созданных admin API. Фактическая страница M02 — `/account/password` (а не `/password`); она меняет пароль, завершает сессию и позволяет войти новым паролем, старый даёт 401.
- Refresh проверяется через настоящий 401: подпись access JWT в sessionStorage заменена невалидной при сохранении role payload; UI `/my/registrations` получает 401, выполняет настоящий refresh 200 и повторяет защищённый запрос 200. Проверены ротация refreshToken, новое содержимое sessionStorage, отсутствие перехода на /login. Токены в evidence не сохраняются.
- 429 — последний project по dependencies core → auth → rate-limit-last. Прозрачный HTTP socket с отдельным loopback source IP отделяет N этого email от прошлых ошибок IP; все ответы даёт настоящий backend. Ограничения повторов/15-минутного окна описаны в README.
- Чек-лист использует штатный reset.sql и psql-переменные для основного/резервного событий, HOME=/tmp во всех четырёх Node-командах, только M09 dump/изолированный restore/verify-latest/cron. Все bash-блоки прошли `bash -n`; серверные команды не выполнялись.
- GET дисциплин вынесен в `getEventDisciplines` API-слоя и переиспользуется организатором/судьёй; поведение QA07-03 сохранено. Setup заранее проверяет установленный tsx с понятной инструкцией `npm ci`.

Публикация/правка у зрителя включает публичный cache TTL 10 с и polling 5 с. Запас до 15 с небольшой; на сервере требуется реальный замер, локальный результат не является запасом на сетевую задержку.

## Не удалось проверить и почему

- Реальную репетицию, Android Chrome/iOS Safari, установку PWA на физических телефонах, серверный бэкап/restore и визуальную приёмку PDF: локальный Chromium не заменяет эти действия. Они включены в отдельный чек-лист.
- **M02 #29 и M09 #25 в main:** п.1в покрыт e2e, серверные backup/restore/cron остаются обязательной приёмкой команды на стенде. M06 #46, M07 #40 и D01 #30 ещё OPEN; только п.1г (waitlist/delaySec) остаётся условным, acceptance включён в чек-лист.
- M03 #33, M04 #38 и M08 #36 также OPEN: серверные PDF/документы/аналитика текущему main недоступны. Проверены существующие браузерные PDF и текущий стиль; готовность всего этапа 1 не утверждается.

Граница QA07-04: защита позднего finish распространяется на другой IN_PROGRESS; вручную выбранный через PUT live не начатый заплыв не покрыт этим исправлением. По инструкции раунда 2 продуктовое условие не расширялось.

Миграции не добавлялись. Пути, методы, DTO и RBAC эндпоинтов не менялись; исправлено поведение существующего POST `/api/v1/competition-units/{id}/finish` при позднем повторе. UI панели судьи использует уже существующий GET `/api/v1/events/{id}/disciplines` вместо legacy-массива события. Матрица QA04 не требует новых строк.
