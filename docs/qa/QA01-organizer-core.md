### Как воспроизвести проверку вручную

1. Поднять локальный PostgreSQL: `cd sport-platform && docker compose up -d postgres`. Передать `JWT_SECRET` как Base64 от тестовой строки не короче 32 байт: текущий `JwtService` декодирует Base64. Например, `JWT_SECRET="$(printf %s 'local-development-secret-must-be-at-least-32-characters-long' | base64 -w0)" /workspace/tools/mvn spring-boot:run -Dspring-boot.run.profiles=local` (в обычном окружении заменить `/workspace/tools/mvn` на `mvn`).
2. На чистой локальной БД запустить `scripts/demo/seed.ts` по README, `API_URL=http://localhost:8080`, `DEMO_SEED_ENABLED=true`, `REQUIRE_VENUE_META=true`. Войти `org@flounder.demo` / `Demo2026!`; `/auth/me` должен содержать organizer без platform_admin.
3. Вызвать генерацию события, валидатор каждого вида и GET sessions. Проверить 0 ERROR, `scheduledAt`, длительность ≤5 с и `estimatedEndsAt`; повторить генерацию и сравнить назначения без случайных ID/runId. Отправить два запроса одновременно и проверить отсутствие дублей в БД.
4. Опубликовать заплывы события дважды. Снять занятую заявку позднего F-100-FREE, дождаться обработки события, пересчитать расписание и прочитать валидатор. Должен быть `PUBLISHED_HEAT_CHANGED/WARNING`, 0 ERROR; соседние дорожки прежние. Анонимно проверить `/api/v1/public/events/{slug}/start-list`, учитывая кеш ≤10 с.
5. Повторить генерацию без force: 409 `scheduling.published_units_exist`. В отдельном тестовом событии вызвать force: заплывы перестроены, WARNING есть, снятая заявка отсутствует.
6. Организатором отправить создание площадки с lanes=7/courseLength=30 и создание события с обратными датами: HTTP 400 и русские ошибки. У DRAFT-события открыть регистрацию, затем повторить публикацию уже PUBLISHED-дисциплины: 400 с русским сообщением и `module.reason`.

## Не удалось проверить и почему

- Браузерная печать A4/PDF, QR и геометрия UI US-4 (§6.4) не проверены: эта проверка выполнена через backend HTTP/MockMvc; браузерная приёмка относится к frontend-QA. Подтверждены публикация и анонимное чтение стартового протокола, но не его печатная вёрстка.
- Продакшен/демо-стенд `sportgate.pro` не изменялся; все записи и замеры сделаны в изолированном локальном окружении. Нагрузочный результат здесь не доказывает скорость на стенде.
- Буквальная команда QA00 с незакодированным `JWT_SECRET=local-development-…` поднимает backend, но login получает HTTP 500 от Base64-декодера. Для завершения ручного прогона использовано Base64-представление той же тестовой строки. Это несовпадение инструкции окружения и требований текущего `JwtService`, identity-код вне QA01 не изменялся.
- Повтор штатного сида с новым суффиксом остановился на повторной публикации общего уже опубликованного регламента: HTTP 400 `regulations.invalid_status_transition`. Повторную идемпотентность самого T10-сида здесь не принимаем; для продолжения использованы API организатора и уже опубликованный регламент. Область исправлений — QA01, код T10/regulations не изменён.
