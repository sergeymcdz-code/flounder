## Покрытие M05

В NotificationIntegrationTest — 16 проверок с настоящей PostgreSQL, в
MailRenderingTest — 3 проверки рендеринга и транспортов:

- Фактическая подача/подтверждение/отклонение → outbox; причина, имя и событие
  сохраняются. Откат транзакции возвращает статус заявки и удаляет outbox.
- Выключенный шаблон блокирует очередь, остальные defaults включены.
- Отсутствующие заявка/аккаунт/будущие события M06 не создают письмо и не ломают
  обработку. Публикация результатов ограничена своим видом; WITHDRAWN исключён.
- Повторная обработка одного publicationId не создаёт дубликат письма.
- UTF-8 multipart plain-text/HTML через мок JavaMailSender; все шесть шаблонов
  с кириллицей, HTML-экранирование причины.
- Logging transport сохраняет SENT в outbox и не вызывает SMTP; INFO содержит
  только адресат/тему, reset-токена и тела там нет.
- Паузы повторов, FAILED на пятой попытке, отсутствие утечки SMTP-ошибки,
  продолжение батча после одного отказа, предел 50 писем.
- Два конкурентных worker с отдельными транзакциями не отправляют одну
  заблокированную строку дважды (SKIP LOCKED).
- Owner/admin может управлять настройками; обычный organizer и чужой организатор
  не могут. Неизвестные/null/повторные настройки атомарно дают 400;
  password_reset выключить нельзя.
- Журнал: проверка EventAccessService, чужой организатор → 403, фильтры и
  отсутствие payload/тел. Все три новых endpoints включены в QA04-матрицу.

Пять frontend-регрессий проверяют сохранение переключателя и сообщение успеха,
ошибку доступа к настройкам, пустой журнал/фильтр, страницы/русские статусы,
отказ доступа к чужому событию.

## Совместное слияние с M02

В отдельном временном worktree объединены код M05 и
origin/feat/M02-auth-hardening 8965239. Разрешены пересечения compose.prod.yaml,
application.yml, README и qa04-endpoints.tsv с сохранением обеих возможностей;
в объединённом env example APP_PUBLIC_URL оставлен пустым. Временный
common.LoggingMailSender **оставлен**, чтобы проверить переходный период.

Команда: `mvn -q test -Dtest=NotificationIntegrationTest,AuthHardeningIntegrationTest,ModulithArchitectureTest,Qa04RoleMatrixIntegrationTest,M02OutboxCompatibilityIntegrationTest`.
Результат: **834 теста в пяти наборах, 0 failures/errors/skipped, код 0**.
`npm run build` объединённого frontend также успешен.

Две дополнительные проверки в этом временном worktree подтвердили, что настоящий
POST /auth/password-reset/request использует Primary OutboxMailSender, создаёт
password_reset с исходной ссылкой M02 и без event_id, затем доставляет в лог при
MAIL_ENABLED=false. Неизвестный аккаунт получает тот же 202 без письма.
Эти две проверки требуют кода M02, поэтому не входят в M05, основанный на main.
Остальные 832 проверки — тесты, уже содержащиеся в объединённых ветках.

В production/main ничего не сливалось; compatibility-ветка не публикуется.
После слияния M02 удалить common/LoggingMailSender.java; общий MailSender оставить.
