# S09. Печатные формы: стартовые номера, карточки заплывов для судей, лист награждения, грамоты

Прочитай `AGENTS.md`, `docs/03_ТЗ_MVP_50_соревнований.md` §3.4 («стартовые номера (bib), карточки заплыва для судей (печать)»), §3.5 («лист награждения (1–3 места по группам), грамоты (шаблон с подстановкой) — серверный PDF»), `docs/02_ТЗ_демо.md` §6.4 (M03: серверные PDF, кеш, лимит двух одновременных рендеров, `documents.busy`), `tasks/M03_Серверные_PDF_протоколы.md` (как устроен модуль `documents`: `DocumentDataService` → `Protocol` → Thymeleaf `templates/documents/*.html` → `PdfRenderer`, шрифты Noto Sans). Ветка `feat/S09-print-forms` от актуального `origin/main`. Модули `documents` (основной), `scheduling` (стартовые номера — новый use case и контроллер-файл), `events` (`settings_json` для шаблона грамоты, без миграции). Один PR. Миграция **V040** (номер зарезервирован). Приоритет: высокий. Слияние после демо 19.10.

## Зачем
На бортике судьям нужны бумажные карточки заплывов (вписать время на каждой дорожке), секретарю — лист награждения для церемонии, организатору — грамоты в день старта без Word. Стартовые номера нужны на карточках, в протоколах и для будущего импорта хронометража (S14). Всё это сейчас делается вручную в Excel/Word.

## Что сделать

### 1. Стартовые номера (модуль `scheduling`, миграция `V040__event_bib_numbers.sql`)
```sql
create table event_bib_numbers (
  event_id uuid not null references events(id) on delete cascade,
  profile_id uuid not null references profiles(id),
  bib_number integer not null check (bib_number > 0),
  assigned_at timestamptz not null default now(),
  primary key (event_id, profile_id),
  unique (event_id, bib_number)
);
```
- `POST /api/v1/events/{eventId}/bib-numbers/assign` `{mode:"BY_CLUB_THEN_NAME"|"BY_NAME", startFrom:1, reassign:false}` (роли `organizer|operator|platform_admin`, `EventAccessService.assertCanModify`) → `{assigned, kept, total}`. Участники = уникальные профили заявок со статусом `CONFIRMED|PAID|ADMITTED` события. `reassign=false` — сохраняет уже выданные номера, новым выдаёт следующие свободные; `reassign=true` — перенумеровать всех (409 `scheduling.bib_locked`, если есть хотя бы один заплыв `IN_PROGRESS|FINISHED|COMPLETED` — после начала стартов номера не меняем). Сортировка детерминирована (клуб, фамилия, имя, дата рождения, id).
- `GET /api/v1/events/{eventId}/bib-numbers` → `[{profileId, bibNumber, lastName, firstName, birthYear, club}]`; `PATCH /api/v1/events/{eventId}/bib-numbers/{profileId}` `{bibNumber}` — ручная правка (409 `scheduling.bib_taken` при занятом).
- Публичный интерфейс `scheduling.BibNumberLookup { Map<UUID profileId, Integer> byEvent(UUID eventId) }` в корне модуля — для `documents`, `publication` и S14.
- Вывод номера: в `ResultsProtocolLookup.Entry` поле не добавлять (чужой модуль); `documents` сопоставляет по `profileId` — проверить, что `Entry` содержит `profileId`/`registrationId`; если нет — добавить `profileId` в `ResultsProtocolLookup.Entry` (минимальное изменение в `results`, перечислить в PR). Стартовый и итоговый PDF (M03) получают колонку «№» (bib) перед фамилией, когда номера назначены; без номеров — колонка скрыта. Публичные страницы — без изменений.

### 2. Карточки заплывов (модуль `documents`)
- `GET /api/v1/events/{eventId}/documents/heat-cards.pdf?disciplineId=&sessionId=&format=A5|A4x2` (organizer/operator, `assertCanManage`): одна карточка на заплыв: шапка (событие, дата, сессия), «Вид № 3 · 50 м вольный стиль, девушки 2014–2015», «Заплыв 2 из 7 · план 10:03», таблица `Дорожка | № | Фамилия Имя | Год | Клуб | Заяв. время | Результат ______ | Прим.` с пустыми полями для рукописного времени (высота строки ≥ 9 мм), подпись «Старший судья ______ Секундометрист ______». `A5` — одна карточка на лист A5 (портрет); `A4x2` — две карточки на A4 с линией разреза. Включать только заплывы в статусе `PUBLISHED|IN_PROGRESS|FINISHED|COMPLETED` (не DRAFT); снятые участники — строка с пометкой «снят». Шаблон `templates/documents/heat-cards.html`, `page-break-after` на карточку.
- Данные — через существующие `DocumentDataService`/`ResultsProtocolLookup.heats` + `BibNumberLookup`.

### 3. Лист награждения (модуль `documents`)
- `GET /api/v1/events/{eventId}/documents/awards.pdf?scope=AGE_GROUP|ABSOLUTE&places=3&disciplineId=` (organizer/operator, `assertCanManage`) и публичный `GET /api/v1/public/events/{slug}/awards.pdf` (те же правила видимости, что у `results.pdf`, кеш 60 с): по видам → группам: `Место | № | Фамилия Имя | Год | Клуб | Результат`, только `FINISHED|COMPLETED` заплывы, места ≤ `places` (по умолчанию 3; ничьи — все с одинаковым местом), группы без результатов пропускаются, заголовок «Лист награждения», колонка-чекбокс «Вручено ☐». Шаблон `awards.html`.

### 4. Грамоты (модуль `documents` + настройка в `events.settings_json`)
- Настройка `settings_json.diploma` (DTO `DiplomaSettings`): `{enabled, title:"ГРАМОТА", bodyTemplate:"награждается {lastName} {firstName} ({birthYear}, {club}), занявший(ая) {place} место на дистанции {discipline} с результатом {result}", footer:"Главный судья ______ Главный секретарь ______", showLogo:false, backgroundFileKey:null}`. Доступные плейсхолдеры: `{lastName} {firstName} {birthYear} {club} {place} {placeText} {discipline} {ageGroup} {result} {eventTitle} {eventDates} {venue} {city}` — неизвестный плейсхолдер → 400 `documents.invalid_template` с перечнем допустимых. `PATCH /api/v1/events/{id}` принимает `diploma` (опционально, прежние поля сохранены; **ровно одна** строка в `EventController`/DTO — чтобы не конфликтовать с S05, который добавляет туда же `payment`; при конфликте оставить оба).
- `GET /api/v1/events/{eventId}/documents/diplomas.pdf?scope=&places=3&disciplineId=&ageGroupCode=` (organizer/operator, `assertCanManage`) → один PDF, по грамоте на страницу A4 (портрет), шрифт крупный, кириллица, фон — при `backgroundFileKey` картинка во всю страницу (загрузка фона `POST /api/v1/events/{eventId}/documents/diploma-background` png/jpg ≤ 5 МБ через `files.FileStorage` без шифрования как публичный ресурс события — если `FileStorage` шифрует всегда, хранить зашифрованно и читать через модуль `files`; описать в PR). Пробная грамота: `GET …/diplomas.pdf?sample=true` — одна страница с тестовыми данными («Иванова Мария») для проверки шаблона. `placeText` — «1-е», «2-е», «3-е».
- Лимит: не более 500 грамот за один запрос (409 `documents.too_many_pages` с подсказкой использовать фильтры); время генерации 200 грамот ≤ 10 с (проверить в тесте с запасом: ≤ 20 с).

### 7. Тесты
- Unit (без Spring): нумерация детерминирована, `reassign=false` сохраняет старые номера, подстановка плейсхолдеров и ошибка на неизвестный, `placeText`.
- Интеграционные (набор M из `docs/scripts/demo/out/set-M.json` или сид теста, как в M03): карточки — число страниц = число опубликованных заплывов (A5) и ⌈n/2⌉ (A4x2), DRAFT не попали, текст содержит «Заплыв 2» и фамилию кириллицей; лист награждения — только места 1–3, ничья даёт два первых; грамоты — страниц = число награждённых, `sample=true` — 1 страница; фон применён (PDFBox: на странице есть изображение); лимит 500 → 409; `assign` после старта с `reassign=true` → 409; чужой организатор → 403; публичный `awards.pdf` не содержит неопубликованных.
- Производительность: 200 грамот ≤ 20 с в тесте (с пометкой `@Tag("slow")`, если проект так помечает долгие тесты — см. QA00).
- Фронт: тесты диалога стартовых номеров и меню печати по образцу `OrganizerHeatsPage.test.tsx`.
