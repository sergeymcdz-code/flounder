# QA02. Результаты, ранжирование, публичное API и live (backend, T06, T08)

Правила — `tasks/QA00_Общие_правила_тестирования.md`. Ветка `qa/QA02-results-public`.

Область: US-6, US-7 (ТЗ §2), §4.8, §5.6, §5.7.

Проверить:
1. Ввод результатов по заплыву ролями operator/judge/organizer: форматы `мм:сс.сс`, `сс.сс`, `ч:мм:сс.сс`, мусор, отрицательные, пустые дорожки; DNS/DNF/DSQ без места; сохранение и пересчёт мест.
2. Ранжирование: абсолют по виду и внутри возрастной группы; равные времена делят место (1,1,3); смешение DSQ и времён; участник без группы.
3. Исправление после публикации: повторная отправка → `CORRECTED`, места пересчитаны, предыдущая таблица в `rule_execution_logs` (kind = RANKING); судья **не** может исправлять опубликованное (если ТЗ так говорит — проверь §2 US-6), operator/organizer могут.
4. Публикация результатов и видимость на публичных эндпоинтах: результаты видны при статусе FINISHED/COMPLETED заплыва; неопубликованные — не видны; `unitsPublished`.
5. Публичные эндпоинты §5.7 (`/api/v1/public/events/{slug}`, `/schedule`, `/start-list`, `/live`, `/results`, `/heats/{unitId}`, поиск «Найти себя»): контракты поле в поле; 404 для чужого/несуществующего slug; без авторизации; никаких персональных данных сверх ТЗ (email, телефон, дата рождения полностью — не должны утекать, только год рождения).
6. Live: установка текущего заплыва, «Старт/Финиш», следующие 3 заплыва, поведение при переходе между сессиями и в конце программы; кеш Caffeine 10 с — обновление укладывается в 15 с (§2 US-7).
7. Производительность: все публичные ответы ≤300 мс на наборе M (T06 §приёмка) — измерь и приведи числа; N+1 запросы (включи `spring.jpa.show-sql`/статистику Hibernate в тесте).
