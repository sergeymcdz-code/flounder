# T00 · Репозиторий, доступы, окружение (делает Сергей, 30–40 мин)

## 1. Создать свой репозиторий с копией кода
1. GitHub → New repository → имя `flounder`, Private, без README. Запомнить URL `https://github.com/<ваш-логин>/flounder`.
2. На ноутбуке (PowerShell, папка `C:\Projects` или любая вне Яндекс/Google Диска — git не дружит с синхронизируемыми папками):
```powershell
cd C:\Projects
git clone https://github.com/Psix10/Flounder.git flounder
cd flounder
git remote rename origin upstream
git remote add origin https://github.com/<ваш-логин>/flounder.git
git push -u origin main
```
3. Сразу убрать секреты и мусор из истории (первая задача T01 сделает это в коде, но секрет уже утёк — его надо сменить): в `sport-platform/.env` поменять `JWT_SECRET` на новый (32+ случайных символа, например `openssl rand -base64 48` или любой генератор паролей). Файл `.env` после T01 из git исчезнет.

## 2. Подключить ChatGPT (Codex)
1. chatgpt.com → Codex → Connect GitHub → выбрать репозиторий `flounder`.
2. В настройках Codex-окружения: образ по умолчанию; setup-скрипт:
```bash
cd sport-platform && mvn -q -DskipTests dependency:go-offline || true
cd frontend && npm ci || npm install
```
Интернет во время выполнения задач — «включён» (нужен Maven Central и npm).
3. В корне репозитория положить файл `AGENTS.md` (готовый текст в `tasks/AGENTS.md`) — Codex читает его перед каждой задачей.
4. Каждое задание запускать как отдельную задачу Codex: вставить текст файла `tasks/T0X_*.md` целиком в поле задачи. Параллельно — не больше 3 задач и только из разных потоков (A/B/C), чтобы не было конфликтов в одних файлах.
5. Когда Codex предлагает PR — создать PR и прислать ссылку Claude на ревью. Не сливать до вердикта «слить».

## 3. Дать доступ Claude
Claude читает публичные и доступные ему репозитории. Для приватного: Settings → Collaborators репозитория — пригласить аккаунт, с которого вы подключали GitHub к claude.ai; либо прислать Claude ссылку на PR и `git diff` текстом. После этого Claude подключит репозиторий через add_repo.

## 4. Сервер для демо (один из вариантов)
- **А. Существующий VPS 24saas.kz**: убедиться, что есть Docker 24+, `docker compose`, 4 ГБ ОЗУ, 10 ГБ свободно, открыты 80/443, есть поддомен (A-запись) на этот IP. Прислать Claude: ОС, `docker -v`, `free -h`, `df -h`, домен.
- **Б. Новый VPS**: Timeweb Cloud (cloud.timeweb.com) → Облачный сервер → Ubuntu 24.04 → 2 vCPU / 4 ГБ / 40 ГБ NVMe (тариф ~1 000–1 300 ₽/мес, оплата помесячно) → регион РФ (Санкт-Петербург/Москва) → SSH-ключ. Поддомен `demo.<домен>` → A-запись на IP сервера. Альтернатива: Selectel, VK Cloud — то же.
- Установка Docker на Ubuntu: `curl -fsSL https://get.docker.com | sh` (выполняет T09).
