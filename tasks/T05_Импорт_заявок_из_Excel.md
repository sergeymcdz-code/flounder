# T05 · Поток A · Импорт заявок из Excel и шаблон (backend)

Прочитай `AGENTS.md`, `docs/02_ТЗ_демо.md` §5.4 (импорт) и §7. Ветка `feat/T05-excel-import` от `main` после слияния T03. Срок: 13–14.10.

## Цель
Организатор загружает Excel с заявками (как у него сейчас в таблицах) и получает заявки в системе и отчёт по ошибкам. 200 строк ≤ 10 с, повторный импорт без дублей.

## Что сделать
1. Новый модуль `imports` (`com.acme.sportplatform.imports`, `package-info` с allowedDependencies: `events, competition, registrations, identity, organizations, common`).
2. Зависимость `org.apache.poi:poi-ooxml` (последняя 5.x). Чтение только `.xlsx`; лимит файла 5 МБ; лимит строк 5 000.
3. `GET /api/v1/events/{eventId}/registrations/import-template` → xlsx с заголовками из ТЗ §5.4, второй строкой-примером, третьим листом «Коды дисциплин» (`code | name`) из дисциплин события. Заголовки должны совпадать с ТЗ символ в символ.
4. `POST /api/v1/events/{eventId}/registrations/import` (multipart `file`, роли organizer/operator/admin, `assertCanManage`):
   - разбор заголовков без учёта регистра/пробелов; незнакомые колонки игнорировать; отсутствие обязательной → 400 с перечнем;
   - по строке: валидация (фамилия/имя непустые; дата `ДД.ММ.ГГГГ` или дата-ячейка Excel; пол `М/Ж/M/F`; код дисциплины существует в событии и дисциплина PUBLISHED; время по `TimeParser` или пусто); пол/год проверить на соответствие группам дисциплины — несоответствие → ошибка строки `не подходит под возрастные группы вида`;
   - профиль: `external_key = lower(фамилия|имя|ГГГГ-ММ-ДД|пол)` без лишних пробелов и «ё→е»; `findOrCreateByExternalKey` (user_id null); обновлять клуб, если пуст;
   - заявка: если по (профиль, дисциплина) уже есть не-WITHDRAWN заявка → `updated` (обновить `seed_time_ms`, если передано), иначе `created` со статусом CONFIRMED, `source = IMPORT`, `payment_status` по взносу дисциплины, `participant_snapshot` заполнен как у формы;
   - вся обработка в одной транзакции на файл? Нет: по строкам, ошибки не откатывают успешные (организатор исправит и дозагрузит); итоговый отчёт по §5.4; запись в `audit_logs` (если таблицы нет — в лог приложения) «импорт: кто, событие, файл, итоги».
5. `GET /api/v1/events/{eventId}/registrations/export` → xlsx всех заявок события (те же колонки + статус, оплата) — для сверки организатором.
6. Тесты: unit на разбор строк (даты в трёх форматах, пол, время, пустые), интеграционный: шаблон → заполнить 5 строк (2 валидные, 1 неизвестный код, 1 плохая дата, 1 дубль) → импорт → отчёт 2/0/… с 2 ошибками → повторный импорт → 0 created, 2 updated.

## Критерии приёмки
- `mvn test` зелёный; импорт готового файла `docs/scripts/demo/out/set-M.xlsx` (200 строк) ≤ 10 с, отчёт `created=200`; `set-M-with-errors.xlsx` → 200 созданных/обновлённых и ровно 3 ошибки (строки 202–204). Добавь интеграционный тест на этих файлах.
- Сообщения об ошибках на русском с указанием строки и колонки.
- Swagger: multipart описан, пример ответа.
