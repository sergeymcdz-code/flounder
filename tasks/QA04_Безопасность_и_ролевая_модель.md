# QA04. Безопасность, ролевая модель, доступ к данным

Правила — `tasks/QA00_Общие_правила_тестирования.md`. Ветка `qa/QA04-security-rbac`.

Проверить и оформить **матрицу роль × эндпоинт** (строки — все эндпоинты `/api/v1/**` из контроллеров, столбцы — аноним, participant, judge, operator, organizer-член организации, organizer другой организации, platform_admin; в ячейке ожидаемый и фактический код). Фактические коды снять интеграционными тестами (можно параметризованный тест по таблице).
1. `EventAccessService.assertCanManage` вызывается на **всех** эндпоинтах организатора/оператора (grep по контроллерам + тест «организатор чужой организации получает 403», IDOR по `eventId`, `disciplineId`, `unitId`, `registrationId` — ID из чужого события).
2. Глобальные роли: `platform_admin`-only эндпоинты (`/api/v1/users/*`, роли, `/actuator/**` кроме health/info); `POST /api/v1/users` открыт — можно ли саморегистрацией получить роль или членство; кто может назначить `memberRole`.
3. JWT: срок, подделка подписи, истёкший токен, токен удалённого/заблокированного пользователя, отсутствие `Authorization`; `JWT_SECRET` только из окружения.
4. Публичные эндпоинты: нет утечки ПДн (email, телефон, полная дата рождения, адрес) в `/api/v1/public/**`; ошибки не раскрывают стек/SQL; `GlobalExceptionHandler` на 500 отдаёт общий текст.
5. Ввод: SQL-инъекции в поиске «Найти себя» и slug (native-запросы в `publication`), XSS через названия (клуб, фамилия) на публичных страницах, слишком длинные строки, загрузка Excel: размер файла, zip-бомба, формулы.
6. Инфраструктура (`infra/`): CORS только для `APP_CORS_ALLOWED_ORIGINS`; заголовки Caddy (HSTS, X-Content-Type-Options, X-Frame-Options/CSP для публичных страниц); `.env` не в git; `DEMO_SEED` в проде; логи без паролей/токенов; rate-limit на `/auth/login` (есть ли — зафиксируй как дефект, если нет, severity major для MVP, minor для демо).
7. Пароли: минимальная длина/политика в `CreateUserRequest`, bcrypt cost, нет смены пароля — отметить.

Отчёт: `docs/qa/QA04-security-rbac.md` с матрицей. Исправлять в PR только явные дыры ≤40 строк (например, пропущенный `assertCanManage`); всё остальное — в отчёт.
