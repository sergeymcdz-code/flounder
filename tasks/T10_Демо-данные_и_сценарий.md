# T10 · Демо-данные (набор M), сид и сценарий демо

Ветка `feat/T10-demo-seed`. Срок: 14.10. Зависит от T03, T05 (импорт) — скрипт работает через HTTP API, поэтому язык скрипта — TypeScript (`scripts/demo/*.ts`, запуск `npx tsx`) или Python (`scripts/demo/*.py`, `requests`, `openpyxl`); выбери TypeScript, чтобы не плодить окружения.

## Что сделать (Codex)
1. Набор M уже сгенерирован: `docs/scripts/demo/out/set-M.xlsx`, `set-M-with-errors.xlsx`, `set-M.json` (генератор `docs/scripts/demo/generate_set_m.py`). Пункт 1 выполнен — пропусти его и используй эти файлы. (Исходная формулировка:) `scripts/demo/generate-set-m.ts` → `scripts/demo/out/set-M.xlsx` и `set-M.json` по ТЗ §7: 200 заявок (≈120 спортсменов, у части по 2 вида), фиксированный seed генератора, вымышленные русские фамилии/имена (списки в скрипте, без реальных людей), годы 2010–2015, клубы 8 шт. («СШОР №1», «Дельфин», «Волна», …), заявочные времена: 50 в/с — 32–50 с, 100 в/с — 1:10–1:55 с зависимостью от возраста; 10 % NT; 3 ошибочные строки (неверная дата, неизвестный код, пустая фамилия) — отдельный файл `set-M-with-errors.xlsx`.
2. `scripts/demo/seed.ts` (параметры: `API_URL`, `ADMIN_EMAIL/PASSWORD`): создаёт организацию «Федерация плавания Самарской области (демо)», площадку «Дворец спорта, 25 м, 8 дорожек» (`venue_meta: {lanes: 8, courseLength: 25}`), пользователей `org@`, `sec@`, `judge@`, `parent@flounder.demo` с ролями и членством, событие «Открытый кубок Самары по плаванию (демо)» на ближайшую субботу, 2 сессии (10:00 и 15:00), 4 вида программы: №1 50 в/с юноши, №2 50 в/с девушки (сессия 1), №3 100 в/с юноши, №4 100 в/с девушки (сессия 2) с группами 2014–2015, 2012–2013, 2010–2011 и режимом BY_AGE_GROUP; публикует событие и открывает регистрацию; импортирует `set-M.xlsx`; НЕ формирует заплывы (это делается вживую на демо). Идемпотентность: повторный запуск не создаёт дублей (ищет по названию/email).
3. `scripts/demo/reset.ts`: удаляет демо-событие и данные (через API, если есть `DELETE`; иначе SQL-скрипт `reset.sql` с комментарием) — чтобы прогонять демо несколько раз.
4. `docs/demo-script.md` — сценарий демо на 12–15 минут с ролями и репликами:
   1) Организатор: обзор события, виды программы, QR на публичную страницу (зрители сканируют с телефона).
   2) Организатор: импорт `set-M-with-errors.xlsx` → отчёт с 3 ошибками → исправленный файл → 200 заявок.
   3) Родитель (телефон): подаёт заявку через форму на 50 в/с и 100 в/с; организатор видит её в списке, подтверждает, отмечает оплату.
   4) Организатор: «Сформировать заплывы» → секундомер → валидатор 0 ошибок → заплывы и расписание → печать стартового протокола (PDF) → публикация.
   5) Телефон: live и «Найти себя».
   6) Организатор: снять участника → пересчитать → показать изменение.
   7) Секретарь: ввод результатов двух заплывов → места → публикация → телефон показывает результат; печать итогового протокола.
   Для каждого шага — что сказать, что показать, какой запасной ход при сбое.
5. Чек-лист репетиции (14.10 вечером) с таймингом и ответственными.

## Критерии приёмки
- `seed.ts` отрабатывает на чистом стенде за ≤ 2 мин и повторно без дублей.
- Сценарий прогнан Сергеем по `demo-script.md` без ошибок; хронометраж ≤ 15 мин.
