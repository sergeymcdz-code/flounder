# QA03. Импорт заявок из Excel, публичная форма, демо-сид и сброс (T05, T10, часть T03)

Правила — `tasks/QA00_Общие_правила_тестирования.md`. Ветка `qa/QA03-import-seed`.

Область: US-2 (ТЗ §2), §5.4, §7, `scripts/demo`.

Проверить:
1. Шаблон Excel скачивается; `set-M.xlsx` (200 строк) импортируется ≤10 с (измерь); `set-M-with-errors.xlsx`: total=203, 200 принято, ровно 3 ошибки — строка 202 дата `31.02.2013`, 203 код `X-999`, 204 пустая фамилия; тексты ошибок на русском и указывают строку.
2. Дедупликация: повторный импорт того же файла → `created=0`, `created+updated+skipped=total`, в базе по-прежнему 200 заявок и 120 профилей; ключ профиля фамилия+имя+дата рождения+пол, ключ заявки профиль+дисциплина; изменение заявочного времени во второй загрузке → `updated`.
3. Испорченные файлы: пустой файл, не-xlsx, лишние/отсутствующие колонки, 5000 строк (не падает, время), кириллица/латиница в кодах дисциплин, пробелы, регистр, дата в текстовом формате, заявочное время в разных форматах.
4. Публичная форма заявки (`POST` из `/e/{slug}/register`): 1–3 вида, заявочное время на каждый, валидация, согласие; заявка попадает к организатору как `SUBMITTED`; подтверждение, `mark-paid` оператором (идемпотентность повторной отметки — зафиксируй фактическое поведение), отклонение; участник видит свои заявки.
5. Сид `scripts/demo/seed.ts`: `npm test`, `npm run typecheck`, повторный запуск без роста сущностей, `--skip-import`, `EVENT_TITLE_SUFFIX`, `DEMO_DATE`; `reset.ts` без флага не удаляет; `reset.sql` удаляет ровно одно событие и не трогает аккаунты/организацию/площадку (прогон на локальной БД); `npm audit` — оцени 2 critical: эксплуатируемы ли в одноразовом скрипте, можно ли обновить без поломки.
