# D01. Визуальный стиль «спорт и управление мероприятием»: концепция и внедрение

Прочитай `AGENTS.md`, `docs/02_ТЗ_демо.md` §6, `docs/03_ТЗ_MVP_50_соревнований.md` §3.6, `docs/design/prototype.html`, `docs/screenshots/*`. Ветка `feat/D01-visual-style` от актуального `main`. Только фронт: `styles/globals.css`, `components/AppLayout.*`, `features/public/Public.module.css`, по одному `*.module.css` на экран, `public/manifest.webmanifest` и иконки. **Логику, разметку компонентов и тексты не менять** (разрешены только добавление классов и обёрток). Один PR в две части: сначала коммит «концепция» (`docs/design/D01_Концепция.md` + скриншоты до/после 3 экранов), затем внедрение. Зависимости: QA06 чинит мелкие дефекты CSS и **не** трогает токены — конфликты в `globals.css` твои; если QA06 слит раньше — ребейзнись.

## Запрос владельца продукта
Сейчас UI — generic admin-template (Inter, голубой primary, карточки с тенями). Нужно: ощущение спортивного события и работы «у бортика» — плотно, контрастно, читаемо с телефона и с проектора, без декоративной «морской темы». Три аудитории: организатор/секретарь за ноутбуком в шумном бассейне (таблицы, крупные статусы, быстрые действия); родитель/зритель с телефона (табло «сейчас плывут», «найти себя», крупные цифры времени); проектор/ТВ (тёмная тема, крупный шрифт).

## Что сделать
1. Концепция (`docs/design/D01_Концепция.md`, кратко, с hex/px): направление и 3 принципа; токены — полная замена `:root` (page/surface/text/muted/border/primary/primary-hover/primary-soft/accent/danger/success/warning + цвета статусов заявок и заплывов DRAFT/PUBLISHED/LIVE/FINISHED/WITHDRAWN/DNS/DNF/DSQ), типографика (один заголовочный и один текстовый шрифт с кириллицей из Google Fonts, самохостинг в `public/fonts` — без внешних запросов; для времени результатов `font-variant-numeric: tabular-nums`), шкала размеров, радиусы (меньше, чем сейчас), тени (почти без), тёмная тема `[data-theme="dark"]` для `/live` и `/results` с переключателем и запоминанием в localStorage; контраст AA проверить и указать значения.
2. Компоненты-характер (CSS в `styles/components.css`, подключить глобально): шапка кабинета с названием события и статусом; карточка заплыва с дорожками, где номера дорожек стилизованы как в бассейне и центральные 4–5 выделены; бейдж статуса; «секундомерное» время результата; блок «Сейчас плывут» на live (крупно, с номером дорожки и фамилией); таблица протокола (плотность, зебра, липкая шапка, моноширинные цифры); кнопки primary/danger/ghost; пустые состояния с подсказкой следующего шага.
3. Экраны-приоритеты (в этом порядке): `/e/{slug}` (лендинг события: крупный заголовок, дата/площадка, 4 кнопки-плитки Протокол/Расписание/Live/Результаты, список сессий как таймлайн), `/e/{slug}/live`, `/e/{slug}/start-list`, кабинет организатора «Заплывы», панель судьи (крупные поля ввода времени для планшета), страница входа. Остальные экраны получают только новые токены.
4. Логотип/иконка PWA: простой знак (SVG кодом, без картинок) — например, стилизованная дорожка/волна в круге; `favicon.svg`, иконки 192/512 (сгенерировать из SVG скриптом в `scripts/` или вручную), `theme_color` в manifest под новую палитру.
5. Печать (`@media print`) не ломать: проверить стартовый и итоговый протоколы в PDF после изменений.
6. Скриншоты до/после в `docs/design/screenshots/` для 6 экранов на 1366 и 375.

## Проверка
`npm test && npm run build && npm run lint`; размер CSS до/после в PR; Lighthouse accessibility ≥90 на `/e/{slug}` и `/live` (приложи числа). В PR: что изменилось по экранам, что не сделано, риски для демо.
