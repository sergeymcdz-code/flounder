# T04 · Поток C · Кабинет организатора: страница события, сессии и виды программы, заявки, заплывы (frontend)

Прочитай `AGENTS.md`, `docs/02_ТЗ_демо.md` §5 (контракты) и §6.1. Ветка `feat/T04-organizer-ui`. Срок: 13–14.10. Бэкенд-эндпоинты из T02/T03 могут быть ещё не слиты — делай по контракту, для локальной разработки используй `VITE_API_MOCK=true` с MSW (`msw` dev-зависимость) и фикстурами из `frontend/src/mocks/` (набор: событие, 2 сессии, 4 дисциплины, 30 заявок, 6 заплывов).

## Контекст
Существует: `features/organizer` (OrganizerLayout, дашборд, `CreateEventPage` 863 строки, `events/:eventId/registrations` — ревью заявок), `api/*.ts` на `apiFetch` (`api/http.ts`), `AuthProvider` с ролями из JWT, CSS Modules + токены в `styles/globals.css`. UI-кита нет — продолжаем в том же стиле; разрешено добавить `@tanstack/react-query` и `qrcode.react`.

## Что сделать
1. **Страница события** `/organizer/events/:eventId` с вкладками (роутинг вложенный): Обзор · Сессии и виды · Заявки · Заплывы · Результаты. В дашборде ссылка на событие ведёт сюда. Существующую страницу ревью заявок перенести во вкладку «Заявки» (маршрут оставить как редирект).
2. **Обзор**: название, даты, площадка (дорожки/длина), статус с кнопками переходов (`publish`, `open-registration`, `close-registration`, `complete`), публичная ссылка `/e/{slug}` с кнопкой «Копировать» и QR (qrcode.react), счётчики: заявок всего/подтверждено/оплачено, заплывов сформировано/опубликовано (из существующих списков, без нового эндпоинта аналитики).
3. **Сессии и виды**: таблица сессий (название, дата-время старта, пауза, «расч. окончание · N заплывов» из `estimatedEndsAt`/`heatsCount`) с добавлением/правкой/удалением; таблица видов программы (№, название, дистанция, стиль, пол, группы, сессия, порядок, статус, заявок) с формой в боковой панели: дистанция (select), стиль (select), пол, возрастные группы (кнопка «Добавить пресет» → `GET /age-group-presets`, либо строки «код/название/пол/от года/до года»), режим посева, сессия, порядок, длительность заплыва (необязательно); кнопка «Опубликовать вид» (существующий publish дисциплины). Валидационные сообщения с бэкенда показывать рядом с полями.
4. **Заявки**: таблица (№, ФИО, год, пол, клуб, вид, заявочное время, статус, оплата, источник, **допуск** — ✓ или причина недопуска по последнему посеву с русской подсказкой; фильтр «Не допущены») с фильтрами по статусу/виду и поиском; действия в строке: подтвердить, вернуть, отклонить, «Оплачено» (`mark-paid`), «Снять» (`withdraw`), правка заявочного времени (inline, `PATCH`). Кнопка «Импорт из Excel» → модальное окно: ссылка «Скачать шаблон» (`import-template`), выбор файла, прогресс, отчёт (создано/обновлено/ошибки таблицей «строка · колонка · сообщение»), кнопка «Закрыть и обновить».
5. **Заплывы**: кнопки «Сформировать заплывы (всё событие)» и по виду; блок результата последнего формирования: длительность, предупреждения; по каждому виду — заголовок и карточки заплывов: «Заплыв 3 · 10:03 · группа Девушки 2014–2015», таблица `Дорожка | Фамилия Имя | Год | Клуб | Заявочное время`, в каждой строке select дорожки (PATCH entry; конфликт → показать ошибку 409); панель «Проверка» (`validate`) с нарушениями (ERROR красным, WARNING жёлтым, клик → подсветка заплыва); кнопки «Пересчитать расписание», «Опубликовать стартовый протокол» (событие), «Открыть печатную форму» (ссылка на `/e/{slug}/start-list?print=1`, см. T07). Если есть опубликованные заплывы — «Сформировать» предупреждает и шлёт `force=true` после подтверждения (окно подтверждения через собственный компонент, не `window.confirm`).
6. **Результаты**: список заплывов с временем, статусом (DRAFT/PUBLISHED/IN_PROGRESS/FINISHED) и «результаты: нет/внесены/опубликованы»; кнопка «Ввести» → `/operator/competition-units/:unitId`; «Опубликовать результаты вида»; ссылка на печатную форму итогового протокола (`/e/{slug}/results?print=1`).
7. **Технические**: `api/sessions.api.ts`, `api/scheduling.api.ts`, `api/imports.api.ts`, типы по контрактам; обработка 401/403 (редирект на вход / сообщение «нет доступа»); состояния загрузки/ошибок через существующие `LoadingState`/`ErrorState`; таблицы с `overflow-x: auto`.

## Критерии приёмки
- `npm run build` и `npm run lint` без ошибок; TypeScript strict.
- На моках весь путь: создать сессию → вид с пресетом групп → импорт (мок-отчёт) → сформировать → увидеть заплывы и дорожки → сменить дорожку → проверить → опубликовать.
- Скриншоты всех вкладок в PR (1280 px и 1024 px).
- Ни одного `any` в новых файлах; названия компонентов и файлов в стиле существующих.
