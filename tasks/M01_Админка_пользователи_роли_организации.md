# M01. Админка платформы: пользователи, роли, организации, члены организаций

Прочитай `AGENTS.md`, `docs/02_ТЗ_демо.md` §1, `docs/03_ТЗ_MVP_50_соревнований.md` §2 и §3.9. Ветка `feat/M01-admin-panel` от актуального `main`. Срок: 14.10 утро. Один PR (backend + frontend).

## Зачем
Сейчас роли и пользователи управляются только через API/SQL. Владельцу продукта нужно из браузера: найти пользователя, выдать/снять роль, посмотреть и создать организацию, добавить людей в организацию с ролью, одобрить заявку на регистрацию организации. Всё — только для `platform_admin`.

## Что уже есть (использовать, не дублировать)
- `identity`: `POST /api/v1/users` (создание), `GET/PATCH/DELETE /api/v1/users/{id}`, `POST /users/{id}/roles` `{roleCode}`, `DELETE /users/{id}/roles/{roleCode}`; роли в таблице `roles` (`platform_admin, organizer, operator, judge, participant`), назначения в `user_role_assignments` (есть необязательные `event_id`, `organization_id`).
- `organizations`: `GET/POST /api/v1/organizations`, `GET /organizations/{id}`, `GET/POST /organizations/{id}/members` (memberRole ∈ owner/admin/member/organizer/operator/judge), заявки `organization-registration-requests` (`approve/reject`, `me/pending`).
- Фронт: `features/admin/SportsAdminPage.tsx`, `RegistrationReviewPage.tsx`, навигация в `components/AppLayout.tsx` (ссылки `/admin/*` только для админа), `api/*.ts` клиенты, `ApiError`.

## Backend (модуль `identity`, при необходимости `organizations`)
1. `GET /api/v1/users?query=&role=&page=&size=` — только `platform_admin`. Поиск по email/фамилии/имени (ILIKE, без учёта регистра), фильтр по коду роли, пагинация (`page` с 0, `size` ≤ 100, по умолчанию 20), сортировка по `created_at desc`. Ответ: `{items:[{id,email,firstName,lastName,status,roles:[code],createdAt}], page, size, total}`. Индекс по `lower(email)` — миграция `V028__users_search_index.sql` (только добавление).
2. `GET /api/v1/users/{id}` — дополнить ответ списком ролей `roles:[{code,name,organizationId?,eventId?}]` и членствами `memberships:[{organizationId, organizationName, memberRole}]`, если ещё нет.
3. `POST /api/v1/users` **админом с явным паролем** уже работает; добавить `PATCH /api/v1/users/{id}/password` `{newPassword}` — только `platform_admin` (минимум 8 символов, bcrypt). Это временная замена отсутствующего «сменить пароль» — отметь в Swagger как admin-only.
4. `PATCH /api/v1/users/{id}` `{status}` — блокировка/разблокировка (`ACTIVE|BLOCKED`): заблокированный не может войти (проверка в `PlatformUserDetailsService`/`LoginUseCase`, код `identity.user_blocked`, сообщение на русском), существующие токены отклоняются в `JwtAuthenticationFilter` (проверка статуса при каждом запросе или кеш 60 с — опиши выбор).
5. Нельзя снять `platform_admin` с самого себя и заблокировать себя (`identity.cannot_modify_self`).
6. `GET /api/v1/organizations/{id}/members` — убедиться, что ответ содержит `userId, email, firstName, lastName, memberRole`; добавить `PATCH /organizations/{id}/members/{userId}` `{memberRole}` и `DELETE /organizations/{id}/members/{userId}` (права: `platform_admin` или `owner/admin` организации через существующую проверку членства). `POST .../members` должен принимать `email` **или** `userId`.
7. `GET /api/v1/organization-registration-requests?status=PENDING` — список для админа, если его нет.
8. Ошибки — `BusinessException(code, message)`, коды `identity.*`/`organizations.*`, сообщения на русском; `GlobalExceptionHandler` дополнить.
9. Тесты: интеграционные (Testcontainers) на поиск/пагинацию, выдачу/снятие роли, блокировку (вход 403/401 + старый токен отклонён), self-protection, членство (добавить по email, сменить роль, удалить), доступ не-админа → 403. `ModulithArchitectureTest` зелёный: `organizations` ищет пользователя по email через `UserLookup` в корне `identity`, не через репозиторий.

## Frontend (`features/admin`, маршруты `/admin/*`, видны только `platform_admin`)
1. `/admin/users` — таблица: email, ФИО, роли (бейджи), статус, создан; поиск (debounce 300 мс), фильтр по роли, пагинация. Действия в строке: «Роли» (чекбоксы по всем ролям из справочника — `GET /api/v1/roles`, добавить эндпоинт если нет), «Заблокировать/Разблокировать», «Сменить пароль» (модалка, два поля, показ/скрытие), «Создать пользователя» (кнопка сверху: email, имя, фамилия, пароль, роли сразу). Подтверждение для блокировки и снятия `platform_admin`. Ошибки API — текстом под формой.
2. `/admin/organizations` — список организаций (название, город, владелец, число членов, число событий если дёшево), создание организации (форма из существующего `POST /organizations`), карточка `/admin/organizations/:id` — члены: добавить по email с выбором memberRole, сменить роль, удалить; ссылка на события организации.
3. `/admin/registration-requests` — очередь заявок на организацию: одобрить/отклонить с причиной (существующий `RegistrationReviewPage` — переиспользовать/перенести в этот раздел, не дублировать).
4. Навигация в `AppLayout`: раздел «Администрирование» с пунктами Пользователи / Организации / Заявки организаций / Виды спорта. Пустые состояния («Пользователи не найдены — измените запрос»), загрузка, ошибки, мобильная ширина не обязательна (админ за ноутбуком), но без горизонтального переполнения на 1366.
5. Тексты на русском; MSW-моки в `src/mocks` для новых эндпоинтов; тесты Vitest на страницу пользователей (поиск, выдача роли, ошибка 403).
