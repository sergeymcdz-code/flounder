# T11. Время на публичных страницах — в часовом поясе площадки

Прочитай `AGENTS.md`, `docs/02_ТЗ_демо.md` §5.7 и §6.3. Ветка `fix/T11-venue-timezone` от актуального `main`. Срок: 13.10 вечер. Один PR, бэкенд + фронт.

## Проблема
Сид создаёт площадку в `Europe/Samara` (UTC+04), сессии 10:00 и 15:00 по Самаре. Публичные страницы (`/e/{slug}`, `/schedule`, `/start-list`, `/live`, `/results`, `/heats/{unitId}`) форматируют `startsAt`/`scheduledAt` в поясе **браузера**: зритель в Москве видит 09:00 и 14:00. Публичное API T06 пояс площадки не отдаёт, хотя в таблице `venues` поле `timezone` есть.

## Что сделать
1. Бэкенд (`publication`): добавить в `GET /api/v1/public/events/{slug}` поле `venue.timezone` (строка IANA, например `Europe/Samara`). Остальные публичные ответы не менять. Обновить `PublicPublicationIntegrationTest` (проверка поля). Кеш не трогать.
2. Фронт (`features/public`): в `public.types.ts` добавить `venue.timezone: string`; в `format.ts` все функции форматирования даты/времени публичных страниц принимают `timeZone` и используют `Intl.DateTimeFormat('ru-RU', { timeZone, … })`; `PublicLayout`/`publicContext` прокидывает `event.venue.timezone` во все публичные страницы. Если поле пустое — fallback на пояс браузера (не падать). Рядом с временем сессии на `/e/{slug}` и `/schedule` показывать подпись пояса один раз: «время местное (UTC+04)» — смещение вычислять из `timeZone` на дату события.
3. MSW-фикстуры и тесты `features/public/*.test.tsx`: добавить `timezone`, тесты на форматирование: `2026-10-17T06:00:00Z` при `Europe/Samara` → `10:00`; при пустом поясе — не падает.
4. Кабинет организатора (`OrganizerProgramPage` и др.) в этой задаче не трогать — отдельно.
