# QA01. Функциональное тестирование ядра организатора (backend, T01–T04)

Правила — `tasks/QA00_Общие_правила_тестирования.md`. Ветка `qa/QA01-organizer-core`.

Область: US-1, US-3, US-4, US-5 (ТЗ §2) и контракты §5.1–5.5.

Проверить (интеграционные тесты Spring + Testcontainers, как в существующих `*IntegrationTest`, плюс ручной прогон, если окружение поднялось):
1. Создание организации/площадки/события/сессий/дисциплин пользователем `organizer` **без** `platform_admin`; `venueMeta {lanes, courseLength}` сохраняется и возвращается; валидация (дорожки 6/8/10, длина 25/50, пустые поля, неверные даты, сессия чужого события).
2. Переходы статусов события и дисциплин (DRAFT → PUBLISHED → REGISTRATION_OPEN → … → FINISHED/COMPLETED): какие запрещены, коды ошибок `module.reason`, сообщения на русском.
3. Посев (§4): по дисциплине и по событию; идемпотентность (повторный запуск = тот же результат); лимиты ≤5 с на наборе M (`rule_execution_logs.duration_ms`); отчёт валидатора: 0 ERROR на корректных данных, все нарушения §4.5 обнаруживаются (подготовь намеренно испорченные заплывы).
4. Расписание (§4.7): `scheduledAt`, пауза между видами, `estimatedEndsAt`, пересчёт.
5. US-5: снятие заявки (WITHDRAWN) для DRAFT-заплывов — полная перестройка; для PUBLISHED — пустая дорожка, WARNING, остальные не двигаются; добавление заявки после посева.
6. Публикация заплывов, повторная публикация, `force`.
7. Граничные случаи: 0 заявок, 1 заявка, заявки без заявочного времени (NT), все одной возрастной группы, число заявок кратно/не кратно дорожкам, возраст на границе группы, участник в двух дисциплинах одной сессии.
8. Конкурентность: два одновременных запуска посева по одному событию — нет дублей заплывов.

Отчёт: `docs/qa/QA01-organizer-core.md`.
