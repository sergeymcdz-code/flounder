# M02. Аутентификация: смена и восстановление пароля, ограничение попыток входа, refresh-токены

Прочитай `AGENTS.md`, `docs/03_ТЗ_MVP_50_соревнований.md` §4 «Безопасность». Ветка `feat/M02-auth-hardening` от актуального `main`. Модуль `identity` + страницы `features/auth`. Один PR. Не пересекаться с M01 (админка): не трогать `UserController` list/roles; общие файлы `SecurityConfig`, `JwtAuthenticationFilter`, `GlobalExceptionHandler` менять минимально и перечислить в PR.

## Backend
1. `POST /api/v1/auth/change-password` `{currentPassword, newPassword}` — для авторизованного; проверка текущего, политика: ≥8 символов, буквы и цифры; код `identity.password_weak` / `identity.password_mismatch`, сообщения на русском.
2. Восстановление: `POST /api/v1/auth/password-reset/request` `{email}` — всегда 202 (не раскрывать, есть ли email); токен (32 байта, `SecureRandom`, хранить **хеш** sha-256) в таблице `password_reset_tokens` (миграция `V029__password_reset_tokens.sql`: id, user_id, token_hash, expires_at (+1 ч), used_at, created_at; индекс по token_hash). Отправка письма — через интерфейс `MailSender` модуля `notifications` если он уже есть (задача M05), иначе — временная реализация `LoggingMailSender` (пишет ссылку в лог уровня INFO с пометкой DEV) и интерфейс в `common`; письмо на русском: «Восстановление пароля Flounder», ссылка `{APP_PUBLIC_URL}/reset-password?token=…`. `POST /api/v1/auth/password-reset/confirm` `{token, newPassword}` — одноразовый, истёкший → `identity.reset_token_invalid`.
3. Ограничение попыток входа: ≥5 неудачных за 15 минут по email **или** IP → 429 `identity.too_many_attempts` с `Retry-After`; хранить в памяти (Caffeine, уже в проекте) — для одного инстанса достаточно; описать в PR, что при >1 сервере нужен Redis.
4. Refresh-токены: `POST /auth/login` дополнительно возвращает `refreshToken` (opaque, 30 дней, хеш в таблице `refresh_tokens` — миграция `V030__refresh_tokens.sql`: id, user_id, token_hash, expires_at, revoked_at, user_agent, created_at); `POST /api/v1/auth/refresh` `{refreshToken}` → новая пара (ротация: старый отзывается); `POST /api/v1/auth/logout` (отзыв текущего) и `POST /api/v1/auth/logout-all` (все устройства). Срок access-токена уменьшить до 1 часа через свойство `app.jwt.access-ttl` (значение по умолчанию прежнее, чтобы не сломать стенд до обновления фронта — объясни в PR). Заблокированный пользователь (M01) → refresh отклоняется.
5. Тесты: интеграционные на каждый сценарий (успех, слабый пароль, неверный текущий, истёкший/повторный reset-токен, 429 после 5 попыток и сброс через 15 мин — с подменой `Clock`, ротация refresh, logout-all).

## Frontend (`features/auth`, `app/providers/AuthProvider`)
1. Страницы `/forgot-password`, `/reset-password?token=`, `/account/password` (смена) — формы с валидацией, русские тексты, состояния загрузки/ошибок/успеха.
2. `AuthProvider`: хранить refreshToken, при 401 от API — один раз обновить токен и повторить запрос (`api/http.ts`), при неудаче — выйти и показать «Сессия истекла, войдите снова». Кнопка «Выйти» вызывает `/auth/logout`.
3. Ссылки «Забыли пароль?» на странице входа и «Сменить пароль» в меню пользователя. MSW-моки, тесты Vitest на refresh-логику и формы.
