# QA00. Общие правила для тестовых агентов (QA01–QA06)

Контекст: демо 15.10.2026, стенд https://sportgate.pro (main = T01–T10). Цель — найти и зафиксировать дефекты до демо, закрыть дешёвые, остальные описать так, чтобы их мог исправить другой агент без вопросов.

Прочитай `AGENTS.md`, `docs/02_ТЗ_демо.md` (§2 сценарии и приёмка, §4 алгоритм, §5 контракты, §6 интерфейс, §8 чек-лист), `docs/demo-script.md`, `scripts/demo/README.md`. Исходник требований — ТЗ; при расхождении кода и ТЗ дефект у кода.

## Ветка и результат
- Ветка `qa/QA0X-короткое-имя` от актуального `main`. Один PR.
- Отчёт `docs/qa/QA0X-<область>.md`: таблица дефектов (ID `QA0X-NN`, severity `blocker|major|minor`, где, шаги воспроизведения, ожидаемо по ТЗ (§), фактически, предлагаемое исправление, файл/строка), затем «Что проверено и прошло» (чтобы было видно покрытие), затем «Не удалось проверить и почему».
- Новые автотесты — обязательны для каждого найденного функционального дефекта (падающий тест фиксирует баг; если починил — тест зелёный). Тесты не удалять и не ослаблять.
- Исправления в том же PR — только в своей области, только если правка ≤ ~40 строк и не меняет контракт API/UI. Остальное — в отчёт с severity. Никаких редизайнов и переформатирования чужого кода.
- Миграции Flyway только добавлять (следующий номер — V028+), существующие не трогать.

## Окружение
- Backend: `cd sport-platform && docker compose up -d postgres && JWT_SECRET="$(openssl rand -base64 48)" mvn spring-boot:run -Dspring-boot.run.profiles=local`. Секрет — Base64 от ≥32 случайных байт: `JwtService` использует `Decoders.BASE64`, обычная строка с дефисами приводит к HTTP 500 при входе. `openssl rand -base64 48` генерирует подходящее значение; не сохраняй его в Git. Если Docker недоступен — так и напиши в отчёте и работай через JUnit-тесты (`mvn -q test`) и статический анализ; не выдумывай результаты ручной проверки.
- Frontend: `cd sport-platform/frontend && npm ci && npm run dev` (с бэкендом) или `VITE_API_MOCK=true npm run dev` (MSW-моки из `src/mocks`).
- Демо-данные: `scripts/demo` (`npx tsx seed.ts`, см. README). Файлы заявок: `docs/scripts/demo/out/set-M.xlsx`, `set-M-with-errors.xlsx`.
- Демо-аккаунты и пароль — `docs/02_ТЗ_демо.md` §1.

## Перед PR
`cd sport-platform && mvn -q test` (или хотя бы `-Dtest='*Test'`), `cd frontend && npm test && npm run build && npm run lint`. В описании PR: число дефектов по severity, что исправлено, что нет и почему, как проверить вручную.
