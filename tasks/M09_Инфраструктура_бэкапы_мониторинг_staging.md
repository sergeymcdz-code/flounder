## Что сделать
1. Бэкапы: `infra/backup.sh` — проверить/доработать: `pg_dump -Fc` в `/home/deploy/backups/flounder-YYYYMMDD-HHMM.dump` + тома файлов (если появится `flounder_files` из M04 — включить), ротация 30 дней, лог в `backups/backup.log`, код возврата ≠0 при ошибке; `infra/restore.sh <dump>` — восстановление в **отдельную** БД `sport_platform_restore_test` и smoke-проверка (`select count(*) from events`), затем удаление тестовой БД; `infra/crontab.example` — ежедневно 03:00 МСК бэкап, еженедельно восстановление-проверка; результат проверки — в алерт (п.2). Раздел в `docs/runbook-demo.md` «Восстановление за 10 минут» пошагово. Опционально — выгрузка дампа во внешнее S3-хранилище в РФ (`rclone`, конфиг через переменные окружения; описать, не включать по умолчанию).
2. Мониторинг: `infra/compose.monitoring.yaml` с Uptime Kuma (проверки `https://sportgate.pro/actuator/health`, публичной страницы события, сертификата) и алертами в Telegram (токен/чат — переменные окружения, инструкция по созданию бота в runbook). Скрипт `infra/alert.sh "текст"` для cron-задач (бэкап упал, восстановление не прошло, диск >85 %). Проверка места на диске в cron.
3. Логи: в `application-prod.yml` — JSON-логи (`logstash-logback-encoder` или встроенный structured logging Spring Boot 3.4+), `correlation-id` фильтр (заголовок `X-Request-Id`, генерируется если нет, попадает в MDC и в ответ), ротация логов docker (`json-file`, max-size 50m, max-file 5 в compose). Sentry: подготовить `SENTRY_DSN` (опционально, выключено без переменной) — `sentry-spring-boot-starter-jakarta` и `@sentry/react` на фронте за флагом `VITE_SENTRY_DSN`.
4. Staging: `infra/compose.staging.yaml` + `infra/deploy-staging.sh` для второго стенда (поддомен `staging.sportgate.pro`, отдельная БД и `.env.staging`), деплой ветки по имени (`./infra/deploy-staging.sh feat/M01-admin-panel`), seed демо-данных включён. Документация в runbook: как поднять на том же сервере (ресурсы: 2 vCPU/4 ГБ — хватит ли; оцени и предложи).
5. CI: `.github/workflows/ci.yml` — добавить `npm test` (сейчас только build/lint — проверь), кеш Maven/npm, запуск `mvn test` с Testcontainers (service docker) если возможно; статус-бейдж в README.
6. Безопасность сервера (в runbook, скриптом `infra/harden.sh` — идемпотентно): `fail2ban` для sshd, отключение входа root по паролю **после** проверки ключа deploy (шаг с явным подтверждением), unattended-upgrades, ufw уже есть.
