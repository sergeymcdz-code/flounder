# M08. Панель аналитики события и организации

Прочитай `AGENTS.md`, `docs/03_ТЗ_MVP_50_соревнований.md` §1 (критерии: время публикации результатов ≤7 мин, сокращение ручных операций) и §3.8. Ветка `feat/M08-analytics` от актуального `main`. Новый модуль `analytics` (`com.acme.sportplatform.analytics`), только чтение через native-запросы (как `publication`) — никаких записей в чужие таблицы. Один PR.

## Backend
1. `GET /api/v1/events/{eventId}/analytics` (`assertCanManage`), один ответ:
   - `registrations`: всего, по статусам, по дням (`[{date, count}]` с даты открытия регистрации), воронка `submitted → confirmed → paid → admitted(в посеве)`;
   - `byDiscipline`: заявки/заплывы/участники по виду; `byAgeGroup`; `byClub` (топ-20 + «прочие»); `byGender`;
   - `sessions`: расчётная длительность (мин), число заплывов, `estimatedEndsAt`, фактическое отставание (если M07 слит — `delaySec`, иначе null);
   - `results`: число опубликованных заплывов, медиана и p95 времени «финиш → публикация» (из `actual_finished_at` M07 или `rule_execution_logs` — зафиксируй источник), число исправлений `CORRECTED`;
   - `validator`: ошибки/предупреждения последнего прогона;
   - `importStats`: последние импорты (строк, создано/обновлено/ошибок, длительность).
   Все суммы — SQL-агрегаты, не вытягивать списки в память; ≤500 мс на наборе M (тест с замером).
2. `GET /api/v1/organizations/{orgId}/analytics` (owner/admin): события по статусам, участники всего и уникальные, повторные участники (профили в ≥2 событиях), средний размер события.
3. `GET …/analytics/export.xlsx` — те же данные листами (Apache POI уже в проекте для импорта).
4. Кеш 60 с (Caffeine) по eventId.

## Frontend
Вкладка «Аналитика» в кабинете события и страница организации: карточки-метрики (крупные цифры), график заявок по дням (линия), воронка (горизонтальные бары), таблицы по видам/клубам, кнопка «Скачать XLSX». Библиотека графиков — лёгкая (`recharts` допустимо; добавь в PR размер бандла до/после). Пустые состояния («Заявок пока нет»). Печать не нужна.

## Тесты
Интеграционные на наборе M: суммы сходятся с прямыми запросами (например, всего заявок = count(*)), воронка монотонна, p95 считается правильно на синтетических данных, 403 чужому, экспорт открывается POI и содержит листы.
