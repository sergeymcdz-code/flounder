# S03 — Производительность, БД и отказоустойчивость стенда (2 vCPU / 4 ГБ)

Ветка `feat/S03-performance-db` от актуального `origin/main`. Один PR. Правила — AGENTS.md. Приоритет: высокий, деплой 16–17.10 до репетиции; задача разбита на часть A (обязательно, безопасно) и часть B (только если A готова и тесты зелёные). Основание — `docs/perf/2026-10-15_perf_audit.md` (прочитать §3–5 перед началом).

Цели (измеряются нагрузочным тестом из п. A7):
- публичные эндпоинты `/api/v1/public/events/{slug}`, `/start-list`, `/schedule`, `/live`, `/results`, `/athletes?q=` — p95 < 300 мс при 50 RPS суммарно, ошибок < 0,5 %;
- API организатора `/organizer/events`, `/events/{id}`, `/events/{id}/registrations`, `/events/{id}/disciplines`, `/event-disciplines/{id}/competition-units`, `/event-disciplines/{id}/results`, `/events/{id}/analytics` — p95 < 500 мс при 10 RPS;
- API в простое < 5 % одного ядра; после `docker restart flounder-api` публичная страница отвечает 200 не позже 90 с.

Не делать: менять контракты ответов (ТЗ §5), пагинацию, опрос фронта (5 с), формат логов, существующие миграции. Новых эндпоинтов нет — `qa04-endpoints.tsv` не меняется (если всё же добавишь эндпоинт — добавь строку).

-- V038: indexes for organizer lists, lifecycle scheduler, public reads and the outbox worker (S03)

create index if not exists idx_notification_outbox_pending on notification_outbox (next_attempt_at)
    where status = 'PENDING';
create index if not exists idx_event_publication_incomplete on event_publication (publication_date)
