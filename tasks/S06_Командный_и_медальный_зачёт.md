# S06. Командный зачёт и медальный зачёт по клубам

Прочитай `AGENTS.md`, `docs/03_ТЗ_MVP_50_соревнований.md` §3.5 («командный зачёт по регламенту (конфигурация очков за места)»), §3.6 (публичные страницы), `docs/02_ТЗ_демо.md` §4.8 (ранжирование: места в абсолюте и по группам, ничьи 1-1-3, DNS/DNF/DSQ без места), §5.7 (публичные представления, видимость только `FINISHED/COMPLETED`). Ветка `feat/S06-team-standings` от актуального `origin/main`. **Новый модуль** `standings` (`com.acme.sportplatform.standings`) со слоями `api/application/domain/infrastructure/web`. Один PR. Миграция **V036** (номер зарезервирован, не менять). Приоритет: высокий. Слияние — после демо 19.10.

## Зачем
Почти в каждом детском и региональном положении есть командный зачёт между клубами/городами и медальный зачёт. Сейчас организатор считает их в Excel после выгрузки протоколов. Нужно считать автоматически из опубликованных результатов, показывать на публичной странице и печатать.

## Что считаем
- **Медальный зачёт**: по каждому клубу — число 1/2/3 мест. По умолчанию — места **в возрастной группе** (`placeInAgeGroup`), опция — в абсолюте (`place`). Сортировка: золото, потом серебро, потом бронза, потом по названию клуба. Ничьи (два первых места) дают медаль каждому.
- **Командный зачёт**: очки за места по таблице `pointsByPlace` (по умолчанию `[9,7,6,5,4,3,2,1]` — 1-е место 9 очков … 8-е 1 очко, как в типовых положениях; организатор задаёт свою таблицу длиной 1–32). Места берутся из той же области (группа или абсолют). Ничья: оба получают очки своего места (1,1,3 → 9,9,6). DNS/DNF/DSQ — 0. Опции: `maxScoredPerClubPerDiscipline` (учитывать не более N лучших результатов клуба в виде/группе, `null` = все), `disciplineIds` (ограничить набор видов, `null` = все), `includeUnpublished=false` всегда для публичной страницы. Итог: сумма очков, при равенстве — больше золотых, потом серебряных, бронзовых, потом по названию.
- Ключ команды — поле `club` снимка участника (как в протоколах). Нормализация: `trim`, схлопывание пробелов, сравнение без регистра; показывать то написание, которое встречается чаще. Пустой клуб → строка «Без клуба» (в зачёте участвует, в PR отметить).
- Источник данных — **только** `results.ResultsProtocolLookup.heats(disciplineIds)` (есть в `main`: `Heat{disciplineId, number, ageGroupCode, status, entries[Entry{club, outcome{place, placeInAgeGroup, status}}]}`) + `competition.EventDisciplineLookup` (список видов события и их возрастные группы) + `events.EventLookup`/`EventPublicLookup`. Через репозитории чужих модулей не ходить; если в `ResultsProtocolLookup.Entry` не хватает поля (например, `ageGroupCode` участника при `BY_TIME_ALL`), добавить минимальное поле в этот интерфейс в модуле `results` и перечислить в PR.
- Учитываются только заплывы со статусом `FINISHED` или `COMPLETED` (как публичные результаты); остальные пропускаются, в ответе — `unitsPending` (число незавершённых заплывов), чтобы UI показывал «предварительный».

## Что сделать

### 1. Миграция `V036__event_standings_config.sql`
```sql
create table event_standings_configs (
  event_id uuid primary key references events(id) on delete cascade,
  enabled boolean not null default false,
  scope varchar(16) not null default 'AGE_GROUP' check (scope in ('AGE_GROUP','ABSOLUTE')),
  points_by_place jsonb not null default '[9,7,6,5,4,3,2,1]',
  max_scored_per_club_per_discipline integer check (max_scored_per_club_per_discipline is null or max_scored_per_club_per_discipline > 0),
  discipline_ids jsonb,                          -- null = все виды
  published boolean not null default false,      -- показывать на публичной странице
  title varchar(255),                            -- «Командный зачёт среди клубов»
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
```

### 2. Домен (чистые классы без Spring, пакет `standings.domain`)
`StandingsCalculator.calculate(config, heats, disciplines) → StandingsResult{medals:[ClubMedals], team:[ClubPoints], unitsPending, disciplinesIncluded, calculatedAt}`; детерминированно; `ClubPoints{club, points, gold, silver, bronze, scoredResults, breakdown:[{disciplineId, ageGroupCode, place, points, athlete}]}` (breakdown — для организатора, в публичный ответ не отдавать по умолчанию, параметр `?details=true` только организатору).

### 3. API
Организатор (роли `organizer|operator|platform_admin`, `EventAccessService.assertCanManage` на чтение, `assertCanModify` на запись):
- `GET /api/v1/events/{eventId}/standings/config` → конфиг (при отсутствии — значения по умолчанию с `enabled=false`).
- `PUT /api/v1/events/{eventId}/standings/config` `{enabled, scope, pointsByPlace, maxScoredPerClubPerDiscipline, disciplineIds, published, title}` → конфиг. Валидация: `pointsByPlace` — массив целых ≥ 0 длиной 1–32, невозрастающий (иначе 400 `standings.invalid_points`, сообщение на русском).
- `GET /api/v1/events/{eventId}/standings?details=true|false` → `StandingsResult` (считается на лету; кеш не нужен).
Публично (без токена, модуль `standings`, путь под `/api/v1/public/**`):
- `GET /api/v1/public/events/{slug}/standings` → `{title, scope, medals, team, unitsPending, calculatedAt, preliminary: unitsPending>0}`; 404 `standings.not_published`, если `enabled=false` или `published=false` или событие не публичное (та же проверка видимости события, что в `publication` — переиспользовать `EventPublicLookup.getPublicBySlug`). Кеш 30 с по slug (Caffeine, как у публичного PDF в M03), `Cache-Control: public, max-age=15`.
- Событие домена `StandingsPublishedEvent(eventId)` при переключении `published` в true — для будущего письма; подписчиков сейчас не добавлять.

### 4. PDF
`GET /api/v1/events/{eventId}/documents/standings.pdf` и `GET /api/v1/public/events/{slug}/standings.pdf` — **в модуле `documents`** по образцу `results.pdf` (`DocumentsController`, шаблон `templates/documents/standings.html`: шапка события, таблица медального зачёта, таблица командного зачёта, подпись «предварительный, не завершено N заплывов» при `unitsPending>0`). Данные брать через новый публичный интерфейс `standings.StandingsLookup` (корень модуля `standings`). Зависимость `documents → standings` допустима (`ModulithArchitectureTest` должен проходить; если тест требует явного объявления зависимостей в `package-info.java` — добавить).

### 5. Фронт
- Организатор: вкладка события «Зачёт» (`/organizer/events/:id/standings`): форма конфигурации (включить, область «по группам/в абсолюте», таблица очков как строка «9,7,6,5,4,3,2,1», лимит на клуб, выбор видов чекбоксами, заголовок, «Показывать публично»), две таблицы результата, кнопки «Обновить», «Скачать PDF», раскрытие «из чего сложилось» (details). Ссылка в навигации `OrganizerEventLayout.tsx`.
- Публично: `/e/:slug/standings` — две таблицы, мобильная вёрстка 375 px (клуб + очки/медали, детали по тапу не нужны), пометка «Предварительный зачёт» при `preliminary`, кнопка «PDF». Ссылка «Зачёт» в `PublicLayout`/карточке `/e/:slug` показывается только если публичный `GET` отдаёт 200 (получать вместе с карточкой — один дополнительный запрос, 404 → ссылку скрыть).
