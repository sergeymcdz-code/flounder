# QA07: регрессия этапа 1

`npm run test:qa07` запускает настоящие M01/M10 e2e; MSW выключен. Нужны локальный backend, PostgreSQL с миграциями, зависимости `scripts/demo` и Chromium. Подготовка backend — как в [QA05-README.md](QA05-README.md).

```sh
cd scripts/demo && npm ci
cd ../../sport-platform/frontend && npm ci
npx playwright install chromium
npm run test:qa07
# При установленном системном браузере:
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium npm run test:qa07
# Независимый повтор семи шагов:
DEMO_DATE=2026-10-24 npm run test:demo
```

`QA07_API_URL` (по умолчанию `http://localhost:8080`) принимает только localhost/127.0.0.1. Адрес должен быть разрешён в CORS. `QA07_PASSWORD` задаёт пароль демо-аккаунтов; `DEMO_DATE` по умолчанию `2026-10-24`. При каждом запуске создаётся событие с уникальным суффиксом « · QA07 …» и импортируется M. Тест создаёт отдельного пользователя и две организации; существующие демо-аккаунты не блокирует и их пароли не меняет. Удаление/SQL-сброс отсутствуют. Запуски QA05/QA07 последовательны: оба используют порт 5173.

- `qa07-admin.spec.ts`: вход администратора, создание/поиск пользователя, выдача/снятие роли с проверкой UI и API, блокировка/разблокировка, 401 старого JWT и отказ входа, смена пароля, создание организации/член по email, одобрение заявки/заявитель становится owner.
- `qa07-judge.spec.ts`: организатор формирует и публикует стартовые протоколы; судья начинает, вводит и публикует первые два заплыва. Проверяются FINISHED, анонимная выдача ≤15 секунд, автообновление DOM зрителя, запрещённое исправление judge (403 без изменения результата), разрешённая правка operator/CORRECTED, два успешных финиша каждого заплыва и переход live/кнопка следующего заплыва.

Журнал сида, UUID/slug, Playwright JSON, trace при ошибке и измеренные задержки — `frontend/work/qa07/`. Это локальные артефакты, их не коммитим. Trace может содержать тестовые токены/пароли: не публикуйте его без очистки. Длительности публикации/правки прикреплены к Playwright-отчёту. Все проверки жёсткие; известных дефектов в новом наборе не маскируем. Намеренно красные backend-регрессии проекта сохраняются в `*IT` с `@Tag("known-defect")` и исключены из обычного `mvn test`.

Условные M02/M06/M07 запускаются только после их появления в main; статус и ограничения зафиксированы в [отчёте QA07](../../../docs/qa/QA07-stage1-regression.md).
